# 논문 연구: 원래 계획, 바뀐 점, 그 이유

> 3성하이닉스 팀 공유용 · 2026-09-30 기준 · 작성 김유환
> 상세 수치: [실험기록.md](실험기록.md) · 현재 계획: [논문계획서.md](논문계획서.md) (사전 등록 원안은 부록 A)

## 한눈에 보기

- 실험은 **모두 끝났다** (Two-Tower 63회 + 베이스라인 4개, Colab L4, 결과는 공유 드라이브 `msrs_paper`).
- 결과를 보기 전에 정한 **주 가설("이미지는 패턴 상품에 더 도움이 된다")은 지지되지 않았다.**
- 대신 **"이미지 효과는 어떤 인코더를 쓰느냐가 결정한다"**는 결과가 모든 확인에서 일관되게 나왔다. 논문은 이 결과를 중심으로 쓰고, 주 가설의 불지지는 그대로 보고하는 방향을 제안한다.
- 팀이 정할 것: 방향 전환 동의, 불지지 서술 방식, 약점 보완 방법, 집필 분담 (맨 아래 6절).

## 1. 원래 계획 (2026-09-28, 결과 보기 전에 확정·커밋)

| 항목 | 내용 |
|---|---|
| 제목 | 패션 추천에서 이미지는 어떤 상품에 도움이 되는가? |
| 주 질문 | 같은 상품군(상의·하의 등) 안에서, 텍스트 대비 이미지가 더해주는 추천 성능이 **패턴·프린트 상품 > 무지 상품**인가 |
| 보조 질문 | 패션 전용 인코더에서 이 차이가 더 커지는가 / 신규 상품에서 이미지 효과가 더 큰가 |
| 데이터 | H&M 실구매, 시간 기준 분할 (마지막 1주 = 테스트) |
| 모델 | 프로젝트 Two-Tower, 상품 쪽은 ID 없이 임베딩만 입력 |
| 인코더 | 텍스트 MiniLM + 이미지 ResNet-50 / CLIP ViT-B/32 / Marqo-FashionSigLIP |
| 대조군 | 이미지 섞기 2종: 전체에서 섞기, 같은 품목 안에서 섞기 |
| 주 검정 (하나만) | Marqo, 재구매가 아닌 구매, "같은 품목 안 섞기" 대비 기여도, 상품군별 (패턴 − 무지) 가중 평균. 95% 구간 하한 > 0이면 가설 지지 |
| 통계 | 고객 단위 짝지은 부트스트랩 1,000회, 주 조건 seed 3개 |

주 검정을 하나로 못박은 이유: 비교할 조합이 많아(상품군 6 × 외관 3 × 인코더 3 × 구간 3) 하나쯤은 우연히 유의하게 나올 수 있어서다.
나머지 비교는 모두 **탐색적 분석**으로 표시하기로 했다.

## 2. 결과 보기 전에 바뀐 것

결과를 모르는 상태에서 바꾼 것이라 **논문의 신뢰도에는 영향이 없다.** 대부분 팀 리뷰를 반영한 것이다.

| # | 원래 | 바뀐 것 | 이유 |
|---|---|---|---|
| 1 | 인코더 세대 비교(6종)가 주 질문 | 상품 유형별 비교가 주 질문, 인코더는 보조 | 인코더 비교는 선행 연구(MoRec, VIP5, Ducho)가 이미 다룸. 3쪽에 비해 규모가 큼 (팀 리뷰) |
| 2 | MMRec 툴킷의 VBPR · FREEDOM | 프로젝트 Two-Tower (ID 없이 임베딩만) | VBPR은 이미지를 무의미한 값으로 바꿔도 성능이 비슷하다는 보고가 있어 결과가 오염될 수 있음. MMRec은 신규 상품을 평가에서 빼버림. 프로젝트와 연결 (팀 리뷰) |
| 3 | 대조군 없음 | 섞은 이미지 대조군 2종 | "모델이 이미지를 안 쓴 것"과 "이미지가 쓸모없는 것"을 구분하기 위해 (팀 리뷰) |
| 4 | 전체 상품 비교 | 같은 상품군 안에서만 패턴 대 무지 비교 (층화) | 패턴 상품이 특정 상품군에 몰려 있으면 상품군 차이를 패턴 차이로 착각함 (팀 리뷰) |
| 5 | 없음 | `product_code`(색상만 다른 상품 묶음) 수준 재채점 | 이미지 효과가 색상 구분 효과로 부풀려질 수 있음 (팀 리뷰) |
| 6 | 테스트 주 3~4개로 신뢰구간 | 고객 단위 부트스트랩 + 학습 seed 3개 | 표본 3~4개로는 구간이 무의미. 학습 무작위성도 반영해야 함 (팀 리뷰 + 자체 검토) |
| 7 | NDCG@12 공동 주 지표 | Recall@300 주 지표 | 상품 5만 개에서 NDCG@12가 너무 작아 잡음에 묻힘 (팀 리뷰) |
| 8 | DeepFashion으로 인코더의 패턴 인식 검증 | 제외 | 3일 안에 끝내기로 해서 (사용 승인 대기 시간) |
| 9 | 상품 약 2만 개 | 53,232개 (해당 기간 판매 + 이미지 있는 상품 전부) | 임의로 자르면 편향. GPU로 충분히 처리 가능 |
| 10 | 외관 그룹 매핑 초안 | `Contrast`, `Application/3D`를 패턴 → 질감·장식 그룹으로 | 실제 값 확인 결과 무지 원단에 장식을 붙인 경우가 많아 패턴 대 무지 비교를 흐림. **실험 전 확정·커밋** |
| 11 | 세 명이 묶음 A·B·C를 나눠 실행 | 한 명(김유환)이 한 GPU로 전부 실행 | 1회 학습이 약 20초로 빨랐음. 같은 GPU에서 돌려 비교가 더 공정해짐 |
| 12 | 하이퍼파라미터 미정 | 후보 3개를 검증 주로 비교 → h2 (학습률 0.0005, 8에폭) | 사전에 정한 규칙(검증 점수 1등) 그대로. 후보 간 차이 0.001로 작음 |

## 3. 결과 (요약)

### 3-1. 주 가설: 지지되지 않음
- 주 검정: **+0.0018, 95% 구간 [−0.0009, +0.0051]** → 구간이 0을 포함 → 사전 등록 기준으로 불지지
- 상품군별로 봐도 테스트 주에 따라 부호가 뒤바뀜 (원피스: main −0.010, 다른 주 +0.015) → 우연한 변동으로 판단

### 3-2. 대신 일관되게 나온 것 (탐색적 분석, seed 3개, 95% 구간)

| 인코더 | 텍스트 대비 이미지 추가 효과 | 신규 상품에서 | 이미지만 썼을 때 |
|---|---|---|---|
| **Marqo (패션 전용)** | **+0.0128** [0.0113, 0.0142] · 상대 +14% | **+0.0234** · 상대 +46% | **0.1034 > 텍스트만 0.0928** |
| CLIP (범용) | +0.0076 [0.0062, 0.0089] | +0.0129 | 0.0806 |
| ResNet-50 (구세대) | +0.0048 [0.0036, 0.0062] | +0.0059 | 0.0745 |

- 인코더 순서 Marqo > CLIP > ResNet: 구간이 서로 겹치지 않음. 패션 전용이 ResNet의 약 2.6배
- 이미지를 섞으면 텍스트만 쓸 때보다도 낮아짐 → 모델이 이미지 내용을 실제로 씀
- 같은 품목 안에서만 섞어도 효과가 사라짐 → 효과는 "무슨 옷인지"가 아니라 디자인·패턴 같은 세밀한 시각 정보에서 옴
- 다른 테스트 주, 색상 변형 합산, 인기도 입력 모델에서도 모두 유지

**왜 의미가 있나:** 최근 연구(Ye 외 2025)는 "이미지는 추천에 거의 기여하지 않는다"고 결론 냈는데, 이미지 인코더로 ResNet-50만 썼다.
우리 결과는 그 결론이 **인코더에 한정된 것**일 수 있음을 보여준다 (원문 확인 후 인용).

### 3-3. 약점: 단순 베이스라인에 크게 짐
- 재구매 + 인기 0.257, 직전 1주 인기 0.230 vs 우리 모델(텍스트 + Marqo) 0.106
- 반면 신규 상품에서는 인기 기반 방법이 0이고 우리 모델만 맞힘

## 4. 결과를 본 뒤 바뀐 것

결과를 본 뒤의 변경이라 **논문에 반드시 "사후·탐색적"이라고 밝혀야 하는 것들**이다. 전부 GitHub 커밋과 실험기록에 날짜와 이유를 남겼다.

| # | 무엇을 | 왜 | 결과 |
|---|---|---|---|
| 1 | **논문 방향 전환**: "어떤 상품에 도움이 되나" → "이미지 효과는 인코더가 결정한다" | 주 가설은 불지지, 인코더 효과는 크고 일관됨 | 계획서 개정. 사전 등록 원안은 부록 A에 수정 없이 보존 |
| 2 | **인기도 입력 모델(D 묶음) 추가**: 상품 쪽에 직전 1·4주 판매량 입력 | 베이스라인 격차 때문에 "원래 약한 모델 위의 효과 아니냐"는 지적 예상 | 격차는 거의 안 줄어듦 (0.1056 → 0.1056). 이미지 효과는 유지(+0.0116) |
| 3 | **인코더 비교에 seed 43·44 추가** (B·C 묶음) | seed 1개로는 인코더 비교를 주장하기 어려움 | seed 3개에서도 순서 유지, 구간 겹치지 않음 |
| 4 | 분석 보강: 기여도 자체의 신뢰구간, 인코더별 그림(그림 2) | 새 방향의 핵심 결과를 보여주기 위해 | 완료 |

**인기도 입력이 효과가 없던 이유 (추정):** 학습 방식이 배치 안의 다른 상품을 오답으로 쓰는데, 인기 상품이 오답으로 자주 뽑혀 모델이 인기도를 깎아내리도록 학습된다.
입력에 인기도를 넣어도 학습 목표가 상쇄한다. 알려진 해법(logQ 보정)이 있지만, 결과를 보고 모델을 또 바꾸는 것이라 하지 않기로 제안한다 (6절).

### 사고 기록: D 묶음이 옛 코드로 돌아간 일
- Colab 런타임을 이어 쓰는 바람에, 새 코드를 받아 놓고도 메모리에 남은 옛 코드로 D 묶음이 학습됨 (인기도 입력 무시)
- 학습 손실이 같은 seed의 텍스트만 조건과 소수점까지 같아서 발견 → D 결과 12개 삭제 후 새 런타임에서 재실행
- 다른 묶음은 영향 없음 (옛 코드와 새 코드의 결과가 완전히 같음을 확인)
- 재발 방지: 노트북 첫 셀이 옛 코드가 메모리에 있으면 멈추고 세션 재시작을 요구하도록 수정. **Colab은 항상 새 런타임으로 시작할 것**

## 6. 팀이 정해야 할 것

1. **방향 전환에 동의하는가.** 제안: 제목과 주장을 "이미지 효과는 인코더가 결정한다"로 바꾸고, 주 가설 불지지는 결과 절에 한 문단으로 정직하게 보고
2. **불지지를 어떻게 쓸 것인가.** 제안: "사전 등록한 가설(패턴 > 무지)은 지지되지 않았다. 이미지 효과는 특정 상품 유형에 몰리지 않고 전반적으로 나타났다"로 쓰고, 사후 분석은 모두 탐색적이라고 명시
3. **베이스라인 격차 보완 방법.** 제안: 결합 후보 분석(재학습 없음). 대안: logQ 보정 재학습(모델이 강해지지만 사후 변경이 하나 더 늘어남)
4. **집필 분담과 마감.** 5절 분담안 확정, 제출 마감일, 목표 학회
5. **upstream 반영.** 실험 코드(`paper/`)와 개정 문서를 팀 레포에 PR로 올릴지
