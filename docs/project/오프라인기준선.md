# 오프라인 기준선 (인기 모델)

> 앞으로 모든 추천 모델은 이 표와 비교한다. 지표 정의는 [지표정의.md](지표정의.md), 평가 코드는 `recsys/`.
> 실행: 2026-10-29, Colab CPU, 코드 `feat/eval-foundation` 4376b96

## 1. 조건

| 항목 | 값 |
|---|---|
| 데이터 | `processed/hm`, `processed/amazon_v2` (source마다 따로 평가) |
| 분할 | test (H&M 마지막 7일, Amazon 시간 순 마지막 5%) |
| 학습 이력 | train + valid, 전체 고객 |
| 정답 | test 구간 `feedback ≥ 1.0` (H&M 구매, Amazon 평점 4 ~ 5점) |
| 평가 고객 | 정답 1개 이상 + 학습 이력 있는 고객. H&M 40,079명 (정답 132,582쌍), Amazon 24,071명 (정답 57,451쌍) |
| 모델 | 학습 이력의 긍정 이벤트 수 상위 k개를 모든 고객에게 같은 순서로. "최근 N일"은 학습 이력 마지막 날 기준 |
| 다양성 임베딩 | `embeddings/v2` 이미지 (Marqo-FashionSigLIP, PCA 256) |

## 4. 해석

1. **H&M은 최근성이 중요하다.** 최근 7일 인기가 전체 기간보다 MAP 2.4배, Recall@300 2배. 패션 판매는 유행 주기가 짧다. 개인화 모델도 최근 이력에 가중치를 주는 방향이 유리할 것.
2. **Amazon은 기간 효과가 거의 없다.** 이벤트가 상품당 약 24개로 듬성듬성하고 분할 구간이 길어서, 최근 30일만 쓰면 오히려 데이터가 부족해진다.
3. **인기 모델은 브랜드 선호를 반영하지 못한다.** Amazon BrandAlignment@12 = 0.2%. 개인화 모델이 이 값을 얼마나 올리는지가 "브랜드 충성도 반영"의 근거가 된다.
4. **Coverage는 12 ÷ 상품 수로 최소값.** 모든 고객이 같은 12개를 받기 때문. 개인화 모델과 비교할 때 기준점.
5. **H&M의 브랜드 지표는 의미 없다.** 단일 브랜드라 다양성 1/12, 일치도 · 충성도 1. 브랜드 관련 주장은 Amazon으로만 한다.

## 5. 재현

```bash
python -m recsys.run_eval --data <msrs_project>/processed/hm --source hm --recent-days 7 \
    --embeddings <msrs_project>/embeddings/v2 --out results/hm_pop_7d_test.json
python -m recsys.run_eval --data <msrs_project>/processed/amazon_v2 --source amazon \
    --embeddings <msrs_project>/embeddings/v2 --out results/amazon_pop_all_test.json
```

결과 파일: 드라이브 `msrs_project/results/baselines/` (JSON 4개, `summary_test.csv`).
