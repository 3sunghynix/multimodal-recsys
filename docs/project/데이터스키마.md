# 통합 데이터 스키마 (v0.3)

> 코드: `backend/app/models.py`. 데이터 현황 · 적재 방법: [data/README.md](../../data/README.md)

## 원칙

- 데이터셋을 나누지 않고 **하나의 상품 · 이벤트 테이블**에 넣고 `source`(amazon · hm · sample · sim)와 `brand_id`로 구분한다.
- 데이터셋 사이에는 고객이 연결되지 않는다. 다중 브랜드 행동은 Amazon 고객과 시뮬레이터 고객에서만 본다.
- 브랜드 충성도는 별도 테이블 없이 이벤트에서 계산한다. 정의: **고객별 최다 브랜드 비중**(최다 브랜드 이벤트 수 / 전체 이벤트 수). "2개 이상 브랜드 구매"는 Amazon 하위 집합에서 고객 100%가 해당해 구분력이 없다.

## 테이블

| 테이블 | 주요 열 | 설명 |
|---|---|---|
| brands | id, name | 브랜드 |
| items | id, source, source_item_id, brand_id, title, description, category, price, image_path, text_embedding, image_embedding | 상품. 임베딩 두 열은 **콘텐츠 임베딩**(인코더 + PCA 256, 검색용, PR #14) |
| users | id, source, source_user_id, persona | 데이터셋 고객 또는 시뮬레이터 고객(페르소나) |
| events | id, user_id, item_id, type, query, model_version_id, experiment_id, variant, created_at | 행동 로그. type: view · click · add_to_cart · purchase · search. Amazon 리뷰는 purchase로 적재 |
| model_versions | id, name, version, status, params | 모델 레지스트리. status: active · candidate · retired |
| experiments | id, name, status, variants | A/B 실험. variants: [{name, model_version_id, weight}] |
| metric_snapshots | id, model_version_id, experiment_id, variant, metric, value, n, created_at | 평가 결과 기록 (대시보드 그래프) |

## 결정된 것

| 항목 | 결정 | 근거 |
|---|---|---|
| 메인 데이터 | Amazon Reviews 2023 Clothing_Shoes_and_Jewelry 5-core, 2021-10 이후, 인기 상품 상위 10만 → 상품 95,662 · 브랜드 23,183 | Amazon_Fashion 카테고리는 3-core에서도 상품 2,065개로 너무 작음 |
| 임베딩 저장 | pgvector (items 열) | PR #14. 검색까지 DB에서 처리 |
| 콘텐츠 임베딩 | 텍스트 all-MiniLM-L6-v2, 이미지 Marqo-FashionSigLIP → L2 → PCA 256 → L2 | 논문과 동일. 질의도 같은 PCA 행렬로 변환 (`embeddings/amazon/pca_*.npz`) |
| 이미지 | 긴 변 384px JPEG, 드라이브에 1만 장 단위 zip. DB에는 경로만 | 평균 21KB, 전체 2.07GB |
| 다중 브랜드 화면 | 상위 50 ~ 100개 브랜드 개별 페이지 + 나머지 "기타" | 상위 100개 브랜드가 이벤트의 21%, 브랜드 절반은 상품 1개 |
| 카탈로그 구성 | Amazon v2(패션 외 상품 제외) + H&M(단일 브랜드, 최근 13주 인기 상품 2만 → 5-core) | 서비스 일관성, H&M 한 브랜드가 카탈로그를 압도하지 않게 |
| 데이터셋 구분 | 모든 표에 `source`, 키는 (source, id) | 데이터셋 사이 고객 · id가 연결되지 않음 |
| 평점 | `feedback`: 4 ~ 5점 +1.0, 3점 +0.5, 1 ~ 2점 −1.0, H&M 구매 +1.0 (평점 C) | 정보를 모두 쓰되 불만족 구매는 부정 신호 |
| 가격 | `price` + `price_source`(real · imputed · scaled) (가격 C) | 모든 상품에 가격, 출처 투명. 화면은 real 외 '예상가' |
| 평가 분할 | H&M 마지막 7일 test · 그 전 7일 valid, Amazon 시간 순 이벤트 마지막 5% test · 그 전 5% valid (`split`) | 팀 전체가 같은 분할로 비교. Amazon은 끝부분이 희소해 7일 기준 불가 |
| 통합 임베딩 | `embeddings/v2`: Amazon v2 + H&M 합쳐 PCA 256 | 같은 공간이어야 하나의 검색 |
| 검색 결합 | 데이터셋별로 후보를 찾고 점수를 source별 표준화 후 합침 | 진단: 두 데이터셋이 임베딩 공간에서 분리(다른 데이터셋 이웃 0.5% 미만), 평균 맞춤으로도 해결 안 됨 |

## 결정할 것

- **items 열 추가 (PR #14 병합 후):** `price_source` (화면 '예상가' 표시용)
- **모델별 상품 벡터 저장:** Two-Tower 등 학습 모델의 128차원 벡터는 모델 · 재학습 버전마다 달라 `items`에 넣지 않는다. 후보: `item_vectors(model_version_id, item_id, vector)` 테이블 vs 모델 산출물 파일(드라이브 `models/{모델}/{버전}/`)
- **스키마 변경 관리:** 지금은 `create_all` + `docker compose down -v`. 변경이 잦아지면 Alembic
- **한국어 검색:** MiniLM은 영어 전용. 한국어 ↔ 영어는 다국어 인코더(임베딩 다시 추출) 또는 질의 번역 중 선택
