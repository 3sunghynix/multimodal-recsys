# 통합 데이터 스키마 (초안 v0.1)

> 코드: `backend/app/models.py`. 확정 전 초안이며 김유환이 Amazon Fashion EDA 후 갱신한다.

## 원칙

- 데이터셋을 나누지 않고 **하나의 상품 · 이벤트 테이블**에 넣고 `source`(amazon · hm · sample · sim)와 `brand_id`로 구분한다.
- 데이터셋 사이에는 고객이 연결되지 않는다. 다중 브랜드 행동(브랜드 충성도)은 Amazon 고객과 시뮬레이터 고객에서만 본다.
- 브랜드 충성도는 별도 테이블 없이 이벤트에서 계산한다 (고객별 브랜드 분포).

## 테이블

| 테이블 | 주요 열 | 설명 |
|---|---|---|
| brands | id, name | 브랜드 |
| items | id, source, source_item_id, brand_id, title, description, category, price, image_path | 상품. 임베딩은 별도 저장(예정: pgvector 열 또는 FAISS 파일) |
| users | id, source, source_user_id, persona | 데이터셋 고객 또는 시뮬레이터 고객(페르소나) |
| events | id, user_id, item_id, type, query, model_version_id, experiment_id, variant, created_at | 행동 로그. type: view · click · add_to_cart · purchase · search |
| model_versions | id, name, version, status, params | 모델 레지스트리. status: active · candidate · retired |
| experiments | id, name, status, variants | A/B 실험. variants: [{name, model_version_id, weight}] |
| metric_snapshots | id, model_version_id, experiment_id, variant, metric, value, n, created_at | 평가 결과 기록 (대시보드 그래프) |

## 결정할 것

- 이미지 저장: 로컬 경로 vs URL, 썸네일 크기
- 임베딩 저장: pgvector(검색까지 DB에서) vs FAISS(빠른 실험)
- Amazon 카테고리 범위와 브랜드 수 (EDA 후)
