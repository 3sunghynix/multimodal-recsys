# 재학습 (지속 학습, 명세 4.6)

> 코드: `recsys/retrain.py` (학습 함수는 `recsys/ume.py` 재사용), 실행: `docker compose run --rm trainer`, 테스트: `recsys/tests/test_retrain.py`

## 1. 흐름

```
서비스 DB 로그 ──▶ trainer (한 번 실행) ──▶ 새 가중치 data/models/ume/retrain_<시각>/
                       │                       └─ report.json (기준 · 새 모델 Recall)
                       ├─▶ model_versions: status="candidate" 로 등록 (나빠지지 않았을 때만)
                       └─▶ metric_snapshots: "<데이터셋>/holdout/recall@20" 기준 · 새 모델 한 줄씩
관리자 ──▶ 대시보드 / POST /models/{id}/activate ──▶ 운영 교체 (trainer는 교체하지 않음)
```

| 단계 | 내용 |
|---|---|
| 실행 조건 | 기준 모델(운영 중 UME)이 학습한 마지막 이벤트(`params.trained_until_event_id`, 없으면 0) 이후 비 setup 이벤트가 `--min-new-logs`(기본 1만) 이상 |
| 학습 표본 | DB 이벤트 중 구매 1.0 · 장바구니 0.5 · 클릭 0.25 (조회는 정답으로 쓰지 않음). 초기 이력(setup)은 학습 이력으로는 쓰고 평가에서는 뺀다 |
| 상품 입력 | 서빙과 같은 DB 임베딩(256차원) — 학습 · 서빙 입력이 어긋나지 않는다 |
| 학습 | 기준 가중치에서 이어서 1 epoch, 학습률 1e-4 (warm start). 구조 · 나머지 설정은 기준의 config.json |
| 평가 | 최근 활동한 고객 10%의 마지막 비 setup 이벤트를 떼어(leave-last-out) 학습에 쓰지 않고, 기준 · 새 모델의 Recall@20을 같은 방식(텍스트 · 이미지 타워 z 합)으로 비교 |
| 채택 | 데이터셋마다 새 Recall ≥ 기준 × (1 − 0.02)면 그 데이터셋은 새 가중치, 아니면 기준 가중치 유지. 하나라도 채택되면 후보 버전 등록 |

## 2. 실행

```bash
docker compose run --rm trainer                                                   # 기본 (1만 건 이상이면 학습 · 등록)
docker compose run --rm trainer python -m recsys.retrain --min-new-logs 0 --no-register   # 조건 무시 · 평가만
docker compose run --rm trainer python -m recsys.retrain --base 3 --tolerance 0           # 기준 버전 지정 · 엄격한 채택
```

등록된 후보는 `GET /models`에서 `status=candidate`, `version=retrain-<시각>`으로 보인다. 교체: `POST /models/{id}/activate`.

## 3. 연결 (다른 모듈)

- **모니터링 runner (광석):** `GET /metrics/log-delta`(#48)로 새 로그 수를 보고 재학습이 필요하면 `docker compose run --rm trainer` 실행. trainer도 같은 조건을 다시 확인하므로 두 번 실행돼도 안전하다.
- **대시보드:** `metric_snapshots`의 `<데이터셋>/holdout/recall@20`으로 기준 · 후보를 비교하고 교체 버튼(`activate`)을 누른다.
- **A/B:** 후보를 바로 운영하지 않고 `POST /experiments`로 기존 운영 모델과 A/B를 걸어 확인할 수도 있다.

## 4. 한계

- 1 epoch 이어서 학습이라 새 로그가 적으면 변화도 작다. 큰 변화(새 데이터셋 · 임베딩 교체)는 Colab 전체 학습(`python -m recsys.ume`)으로 한다.
- 평가는 서비스 로그 안의 다음 행동 맞히기라, 시뮬레이터 로그만 있을 때는 시뮬레이터 행동 규칙을 맞히는 정도를 본다.
- 학습 시간: CPU에서 데이터셋 · 모달리티마다 수 분 (이벤트 수에 비례).
