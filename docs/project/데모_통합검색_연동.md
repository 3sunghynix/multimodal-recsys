# 데모 통합 검색 연결 — 구현·검증 기록

작성: 김광석 / 2026-10-29

## 1. 변경 목적과 기준

팀 리뷰의 주말 데모 전 필수 항목인 **통합 POST /search 연결**을 구현했다. 기준 문서는 `docs/project/검색.md` 3·4장이다.

작업 기준은 기존에 내려받은 데모 PR #21의 head `a789365aaa2bdb065b995aa5eaeb4d0d40d82f14`다. 최신 원격 상태는 다시 확인하지 못했다. PR #20의 검색 API는 이 사본에 포함되어 있다. 유환의 PR #22 리뷰 요청에 대한 추가 변경이다. 기존 eval-metrics 브랜치에 추가해 PR #22를 갱신한다. 새 PR은 만들지 않는다. 이 HTML을 실제로 서빙하는 /app 라우트와 Docker 프론트 복사는 데모 PR #21의 변경이므로, 실행 환경에 해당 코드가 포함돼 있어야 한다. 이후 프론트 수정과 충돌하는지도 확인한다.

## 2. 동작

1. 검색어만 입력하면 텍스트 검색, 이미지만 선택하면 이미지 검색이다. 둘을 함께 입력하면 결합 검색이다.
2. 파일 선택은 업로드 준비만 한다. 검색 버튼이나 Enter로 한 번 요청한다. 이미지 선택 후 슬라이더를 조정할 시간을 주기 위해 자동 업로드하지 않는다.
3. 두 입력이 있을 때만 우선순위 슬라이더를 표시한다. 기본 text_weight=0.5, 왼쪽 끝은 이미지 우선(0), 오른쪽 끝은 텍스트 우선(1)이다. 입력 비율을 숫자로도 표시한다.
4. FormData에 q(있을 때), file(있을 때), text_weight, k=20을 넣어 POST /search로 보낸다. multipart Content-Type 경계는 브라우저가 설정하게 둔다. merge를 생략해 서버 기본 per_source_rank를 사용한다.
5. SearchOut.items의 상세 정보로 상품 카드를 그린다. 검색에서는 /items를 추가 호출하지 않는다. 추천은 기존대로 ID를 반환하므로 /items 상세 조회를 유지한다.
6. query_en을 ‘…(으)로 검색했습니다’로, untranslated를 ‘번역 못한 단어’로 표시한다. 다음 검색·추천 시 이전 안내를 지운다.
7. 이미지 제거 버튼으로 텍스트 전용 검색으로 돌아갈 수 있다. 선택 이미지는 성공 후에도 유지해 재검색에 사용한다.

## 3. 함께 보완한 프론트 처리

- 검색어·상품명·번역·파일명·오류는 HTML 문자열로 삽입하지 않고 DOM/textContent로 표시한다.
- 허용 형식·빈 파일·10MB 상한을 프론트에서 먼저 검사한다. 서버 검증을 대체하지 않는다.
- HTTP 오류·연결 실패를 표시하고 재시도를 허용한다. 이전 결과를 현재 검색 결과처럼 남기지 않는다.
- 검색과 추천 사이 빠른 전환에서는 이전 요청을 취소하고 마지막 요청만 결과를 표시한다.
- 현재 API에 price_source가 없으므로 기존 고정 환산 가격은 모두 ‘예상가’로 표시한다. 툴팁에 데모 환산 기준(1 USD=1,300 KRW)을 명시한다. 실시간 환율·실제 판매가라는 주장은 하지 않는다. 출처별 표시 계약은 후속 작업이다.

## 4. 검증 방법

### 브라우저 동작 검사

테스트는 실제 HTML을 Chrome/Chromium에서 실행하고 HTTP API 응답만 대역으로 바꾼다. 모델 다운로드·DB·상품 데이터가 없어도 입력과 요청·표시 계약을 확인할 수 있다.

```bash
cd tests/frontend
npm install
npx playwright install chromium
npm test
```

설치된 Google Chrome을 쓰려면 `MSRS_TEST_BROWSER_CHANNEL=chrome npm test`로 실행할 수 있다. Playwright는 테스트 전용 개발 의존성이며 서비스 Docker/Python 의존성을 바꾸지 않는다.

총 13개 시나리오를 확인했다: 한국어 multipart 요청과 추가 상세 요청 없음, 이미지 단독, 결합 비중 0·0.3·1, 이미지 제거, 미번역 안내 초기화, 빈 입력, 잘못된 이미지, HTTP 오류와 복구, 연결 실패, 동적 마크업 안전 표시, 늦은 응답 무시, 추천 회귀, 모바일 화면.

### 기존 백엔드 검사

기존 backend 테스트 18개가 별도 임시 Python 환경에서 통과했다. 가짜 인코더로 통합 검색의 한국어 변환·source 혼합 등을 확인하는 기존 테스트가 포함된다. 이번 변경에서 백엔드 서비스 코드는 수정하지 않았다.

```bash
cd backend
python -m pytest -q
```

### 실제 데모 확인 — 팀 확인 필요

- PR #21 코드가 포함된 환경에서 데이터와 인코더/PCA를 준비한다. 경로와 준비물은 기존 `검색.md`를 따른다.
- 서버 시작 후 이미지를 처음 적재하는 경우 기존 PR #21의 정적 경로 등록 문제로 이미지가 404일 수 있다. 이 변경에서는 서버 마운트 방식을 바꾸지 않았다. 초기화/재시작 절차 또는 해당 수정 여부를 확인한다.
- /app/에서 ‘검은색 원피스’ → query_en·카드 확인, 이미지 단독, 텍스트+이미지 비중 변경, 미번역 단어 안내를 확인한다.
- 개발자 도구 Network에서 검색 한 번에 POST /search를 호출하고 GET /search·POST /search/image·검색용 /items가 추가로 발생하지 않는지 확인한다. 상품 이미지 GET 요청은 정상이다.
- API 대역 테스트는 실제 검색 관련도·지연·상품 출처 비율을 검증한 결과가 아니다. 실제 Docker/PostgreSQL·전체 인코더 실행은 이번 작업에서 수행하지 않았다.

## 5. 후속 작업

리뷰의 2~4번은 별도 후속 작업으로 남긴다.

- 검색·노출·클릭 로그 전송: 귀속·중복 방지 계약과 합의 후 구현. 현재 화면은 POST /events를 호출하지 않는다.
- /items 전용 테스트: 순서·400·404 등 백엔드 테스트 추가.
- 서버 ItemOut의 image_url 계약: 경로 변환 책임을 서버로 옮기는 변경. 현재는 기존 image_path 규약을 유지한다.

## 6. 발표에서 설명할 것

‘검색어와 사진을 한 API로 보내고, 서버가 번역과 두 데이터셋의 검색 결과 결합을 처리한다. 화면은 결과와 번역 한계를 보여 준다. 슬라이더는 텍스트와 업로드 이미지 사이의 가중치이며, 모델을 새로 학습하거나 추천 모델을 교체하는 버튼이 아니다.’

‘자동 브라우저 테스트는 연결 방식과 화면 동작 검증이다. 실제 검색 품질이나 A/B 개선 효과를 입증한 실험으로 소개하지 않는다.’
