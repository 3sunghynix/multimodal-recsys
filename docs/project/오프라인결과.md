# 오프라인 결과 — 개인화 추천 (UME)

> 설계: [추천모델설계.md](추천모델설계.md), 기준선: [오프라인기준선.md](오프라인기준선.md), 지표: [지표정의.md](지표정의.md)
> 코드: `recsys/ume.py` (`python -m recsys.ume --root <msrs_project> --source {hm,amazon} --split {valid,test}`), Colab L4, 2026-10-29

## 1. 조건

| 항목 | 값 |
|---|---|
| 데이터 · 분할 | `processed/hm`, `processed/amazon_v2`. 설정 선택은 **valid** (학습 = train), 최종 확인은 **test 한 번** (학습 = train + valid) |
| 평가 고객 | H&M 41,919 · Amazon 35,149 (valid, 정답 1개 이상 + 학습 이력) |
| 입력 | `embeddings/v2` 256차원 (서비스 DB와 같은 것) |
| 모델 | 데이터셋마다 텍스트 · 이미지 Two-Tower 따로 (512 → 128, temperature 0.05, 8 epoch, batch 2048, 이력 50) |
| 학습 표본 | 이벤트 단위, 같은 시각 구매는 이력에서 제외. H&M 135만 · Amazon 146만. 정답 가중치 = feedback |
| 학습 시간 | 모델당 약 20초 (L4). 데이터셋당 2개 |
| 점수 | UME = z(텍스트) + z(이미지), 고객별 표준화 · **+ γ · 인기 점수**(학습 이력 긍정 수 log1p 표준화; H&M 최근 7일, Amazon 전체 기간) · **+ β · [고객 최다 브랜드]** |

## 2. valid 결과

### H&M

| 모델 | Recall@12 | NDCG@12 | MAP@12 | Recall@300 | Coverage@12 |
|---|---:|---:|---:|---:|---:|
| 인기 (최근 7일) | 0.0216 | 0.0126 | 0.0060 | 0.215 | 0.0006 |
| 텍스트 | 0.0271 | 0.0177 | 0.0105 | 0.143 | 0.94 |
| 이미지 | 0.0261 | 0.0170 | 0.0100 | 0.154 | 0.97 |
| UME | 0.0354 | 0.0238 | 0.0147 | 0.176 | 0.96 |
| 인기 280 + UME 20 (논문 설정) | 0.0216 | 0.0126 | 0.0060 | 0.243 | 0.0006 |
| UME + 인기 γ=1 | 0.0538 | 0.0356 | 0.0214 | 0.276 | 0.62 |
| **UME + 인기 γ=2** | **0.0546** | **0.0365** | **0.0216** | **0.310** | 0.33 |
| UME + 인기 γ=4 | 0.0446 | 0.0293 | 0.0165 | 0.292 | 0.08 |

- UME가 단일 모달리티보다 MAP +40% (텍스트 0.0105 → 0.0147): **논문 결과(+39%) 재현**.
- 인기를 점수로 섞으면(γ) 슬롯으로 끼우는 것보다 훨씬 좋다. γ=2가 인기 모델 대비 MAP **3.6배**, Recall@300 +44%.

### Amazon

| 모델 | Recall@12 | NDCG@12 | MAP@12 | Recall@300 | 브랜드 일치도@12 | Coverage@12 |
|---|---:|---:|---:|---:|---:|---:|
| 인기 (전체 기간) | 0.0140 | 0.0111 | 0.0087 | 0.063 | 0.002 | 0.0001 |
| UME | 0.0075 | 0.0039 | 0.0021 | 0.070 | 0.115 | 0.76 |
| UME + 브랜드 β=2 | 0.0080 | 0.0040 | 0.0021 | 0.070 | 0.576 | 0.76 |
| UME + 인기 γ=1 | 0.0202 | 0.0138 | 0.0096 | 0.113 | 0.080 | 0.16 |
| UME + 인기 γ=1 + 브랜드 β=2 | 0.0192 | 0.0122 | 0.0081 | 0.112 | 0.365 | 0.28 |
| UME + 인기 γ=2 | 0.0199 | 0.0140 | 0.0100 | 0.106 | 0.039 | 0.03 |
| **UME + 인기 γ=2 + 브랜드 β=2** | **0.0201** | **0.0140** | **0.0101** | **0.108** | **0.156** | 0.06 |

- UME 단독은 상위 12개에서 인기보다 약하다 (MAP 0.0021 vs 0.0087). Amazon 리뷰는 그 시기 인기 상품에 몰리고, 콘텐츠 모델에는 인기 신호가 없다.
- 인기 점수를 섞으면 인기 모델을 넘는다. γ=2 + β=2: MAP +16%, Recall@12 +44%, Recall@300 +71%, **브랜드 일치도 0.2% → 15.6%**.
- 브랜드 가산은 정확도를 거의 잃지 않고 브랜드 일치도를 올린다. 더 올리면(γ=1, β=2 → 36.5%) MAP가 인기보다 7% 낮아지는 교환 관계 → 관리자 화면 β 슬라이더.

전체 표(인기 슬롯 · 모든 γ × β 조합): 드라이브 `results/ume/{hm,amazon}_valid_pca.json`.

## 3. 결정 (test 전에 고정)

| 데이터셋 | 서비스 기본 설정 | 근거 |
|---|---|---|
| H&M | UME + 인기 γ=2 (최근 7일) | valid MAP@12 · Recall@300 최고 |
| Amazon | UME + 인기 γ=2 (전체 기간) + 브랜드 β=2 | valid MAP@12 최고이면서 브랜드 일치도 가장 높은 조합 |

- 여러 설정 중 valid로 고른 값이므로 valid 숫자는 낙관적이다. **test는 위 설정만 한 번** 확인한다.
- 인기 슬롯 방식(`ume+pop*`, `pop280+ume20`)은 쓰지 않는다.
- 아직 안 한 것: E0 (원본 임베딩 · 주 단위 표본 비교), E4 (feedback 가중치 효과), 상품 구간별 지표.

## 4. test 결과 (3장 설정만, 한 번)

평가 고객 H&M 40,079 · Amazon 24,071 (기준선과 같은 집합). 인기 모델 숫자는 [오프라인기준선.md](오프라인기준선.md)와 같다.

| 데이터셋 | 모델 | Recall@12 | NDCG@12 | MAP@12 | Recall@300 | 브랜드 일치도@12 | Coverage@12 |
|---|---|---:|---:|---:|---:|---:|---:|
| H&M | 인기 (최근 7일) | 0.0255 | 0.0166 | 0.0091 | 0.235 | (1) | 0.0006 |
| H&M | **UME + 인기 γ=2** | **0.0626** | **0.0413** | **0.0246** | **0.330** | (1) | 0.31 |
| Amazon | 인기 (전체 기간) | 0.0132 | 0.0106 | 0.0079 | 0.054 | 0.002 | 0.0001 |
| Amazon | **UME + 인기 γ=2 + 브랜드 β=2** | **0.0193** | **0.0134** | **0.0091** | **0.099** | **0.111** | 0.04 |

| 인기 모델 대비 | Recall@12 | MAP@12 | Recall@300 | 브랜드 일치도@12 |
|---|---:|---:|---:|---:|
| H&M | ×2.5 | ×2.7 | +41% | — |
| Amazon | +46% | +15% | +84% | 0.2% → 11.1% (×56) |

- valid와 같은 방향 · 비슷한 크기로 재현됐다 (H&M MAP 3.6배 → 2.7배, Amazon MAP +16% → +15%).
- 참고(사전 결정 외): H&M에서 UME가 텍스트 단독보다 MAP +44% (0.0107 → 0.0154) — 논문 결과와 같은 크기.
- 재실행해도 숫자가 같다 (학습 결정적).
- 위 Amazon 숫자는 선호 브랜드를 **전체 이력**(부정 리뷰 포함)으로 계산한 버전이다. PR #23 리뷰로 긍정 이력만 쓰도록 고쳤으므로(e3f06ec) Amazon test를 같은 설정으로 다시 확인한다.

- **서비스 설정은 두 데이터셋 모든 지표에서 구간이 0보다 크다** → 인기 기준선보다 좋다는 결론 확정.
- 참고: 인기 점수 없는 UME 단독은 Amazon 상위 12개에서 인기보다 나쁘고(MAP −76% [−87%, −64%]) Recall@300만 좋다(+39%). H&M은 상위 12개는 좋고(MAP +69%) Recall@300은 나쁘다(−23%). 두 경우 모두 인기 점수를 섞어야 양쪽에서 이긴다.
- 커버리지는 UME 단독(0.68 ~ 0.95)보다 크게 줄었다 (γ=2에서 인기 상품 비중이 커짐). 다양성이 필요한 화면은 γ를 낮추는 선택지가 있다 (valid H&M γ=1: MAP 거의 같고 커버리지 0.62).
