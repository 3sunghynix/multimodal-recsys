## 3. 분류 규칙

1. **대분류:** 대상 열(cat_target)과 경로에서 Women · Men · Girls · Boys · Baby · Kids 등을 찾는다. 없으면 공용 (예: H&M "Sport").
2. **중 · 소분류:** 경로를 깊은 단계부터 보며 처음 맞는 규칙. 규칙 순서가 우선순위 (예: 'vest top' → 민소매가 'vest' → 조끼보다 먼저, 'dress shirt' → 셔츠가 'dress' → 원피스보다 먼저).
3. **일반 규칙 보정:** 세트 · 플랫 · 기타 신발 · 기타 상의 · 기타 액세서리에 걸리면 윗단계에서 구체적인 규칙을 다시 찾는다 (예: "Sleep & Lounge > Sets" → 잠옷, "Sandals > Flats" → 샌들).
4. **상품명 보완:** 경로에 품목 정보가 없으면("Women > Clothing"에서 끝남 등) 상품명으로 찾는다. 수식어(소매 길이 · 운동 종류 · 핏 · 무늬)를 먼저 지운다 — "Running Shorts"가 운동화, "Bootcut Jeans"가 부츠가 되지 않게. 이 단계로 '기타'가 1.68% → 0.06%.
5. Amazon 공통 최상위 단계 "Clothing, Shoes & Jewelry"는 'Shoes'가 들어 있어 판단에서 뺀다.

## 4. 검증

- 단위 테스트 26개: 헷갈리기 쉬운 경로 · 상품명 사례 (sweatshirt ≠ 티셔츠, ear cuff ≠ 스카프, 안경 케이스 ≠ 선글라스 등)
- 무작위 표본 40개 눈으로 확인: 38개 맞음. 틀린 2개 중 1개(귀 커프 → 스카프)는 규칙 보완, 1개는 원본 경로 오류(수영 파카가 "Robes" 아래)

## 5. 사용

- 데이터 묶음(`exports/full_catalog`, `dev_subset`)의 items.parquet에 `category_l1 · category_l2 · category_l3` 열로 저장.
- 적재 스크립트(`backend/scripts/load_dev_subset.py`)는 이 열이 있으면 DB `items.category`를 "여성 > 상의 > 티셔츠" 형식으로 넣는다.
- 쓰는 곳: 시뮬레이터 페르소나 선호 카테고리([페르소나_v0.3.md](페르소나_v0.3.md)), 관리자 데이터 현황 화면의 카테고리 트리, 검색어 생성.
- 다시 계산: `from recsys.taxonomy import classify_frame` → `classify_frame(items)` (열: categories · cat_target · cat_type · title).
