# 관리자 대시보드 v0.1 — 구현·발표 메모

## 왜 Streamlit인가

학교 미션 6절에 Streamlit(대시보드), 최종 결과물에 localhost:8501 평가·A/B 화면이 명시돼 있다. 기존 FastAPI API·쇼핑 데모와 분리한 Streamlit 컨테이너를 추가했다. 화면 프레임워크 선택을 미정으로 두던 이전 설계에서 구체화한 부분이다.

## 화면별 현재 상태

| 화면 | 구현한 것 | 아직 없는 것 |
|---|---|---|
| 개요 | 파일/온라인 기능 상태, GET health/models 수동 조회와 조회 시각 | 실시간 추이·알림 API 연결 |
| 모델 실험실 | 파일 선택·source·모델 4개까지 비교, 주요 지표·차트·표·CSV | 모델 활성화·가중치 수정·재학습 |
| A/B 테스트 | 필요한 전환율·p-value·CI·표본 조건 안내 | 온라인 통계 검정 및 판정 |
| 알림·재학습 | 후속 단계 표시, 비활성 컨트롤 | 모니터·트리거·작업 큐·롤백 |
| 시뮬레이터 | 실제 local summary 파일의 건수·제외 사유·CTR | 서버 실행 제어 및 실제 UME A/B |
| 데이터 현황 | dev parquet 행·열 수 | 전체 DB 통계·전체 카탈로그 상태 |

## 숫자를 구분하는 원칙

1. 원본 test JSON이 있으면 우선 사용하고, 없을 때는 PR #23의 **문서 보고값(반올림)**이다. 출처 `b05ff92`와 입력 공간 `embeddings/v2`를 보존했다. 원본 실행 결과가 아니므로 원시 수치의 정밀도·새 검증을 주장하지 않는다.
2. 사용자가 평가 JSON을 넣으면 기록된 수치만 읽는다. 오프라인 모델을 실행하거나 기존 `recsys/eval` 계산을 복제하지 않는다.
3. 같은 source/split/파일 안의 모델만 비교한다. source가 다른 수치를 하나의 모델 성능으로 평균내지 않는다.
4. Coverage·브랜드 일치도가 높다고 무조건 좋다고 표시하지 않는다. 브랜드 일치도@12와 고객별 최다 브랜드 비중은 다른 지표다.
5. 신뢰구간은 실제 결과 파일의 vs_popularity에 있을 때만 표시한다. 오프라인 구간을 온라인 A/B 구간으로 사용하지 않는다.
6. simulator summary는 **로컬 합성 행동**이다. 실제 고객 전환율이 아니다. 페르소나 간 CTR 순위로 모델 품질을 판단하지 않는다.
7. 모델 레지스트리 GET 응답은 현재 조회 시점의 서버 기록이다. 문서 UME와 같은 버전인지 자동으로 연결하지 않는다.

## 발표할 때 말할 수 있는 것

“평가 모듈이 만든 결과를 운영자가 읽고 비교할 수 있도록 Streamlit 모델 실험실을 구현했습니다. 기본 화면에는 출처가 있는 문서 보고값을 보여주고, 원본 평가 JSON도 가져올 수 있습니다. 시뮬레이터의 187명 결과는 따로 합성 결과로 표시합니다. 운영 모델 변경이나 재학습은 아직 실행하지 않고 후속 API·확인 절차와 연결할 예정입니다.”

## 검증 범위

Python의 파서·기준값 0·누락 지표·오류 파일·AppTest 화면 상호작용을 검사한다. 로컬 Streamlit 서버와 브라우저에서 6개 메뉴와 모바일 화면을 확인한다. 기존 모델 학습이나 검색 품질을 재평가한 것은 아니다. Docker 이미지 빌드 여부는 검증 기록과 구분해서 적는다.

## 다음 작업

- API의 model_version_id와 평가 산출물 연결, 활성화 확인·감사 기록·롤백 계약.
- 운영 정책이 정해지면 모니터·재학습 작업 API와 연결.


## 리뷰 반영

- source별 원본 test 결과 JSON을 우선 읽고 없으면 문서 스냅샷을 사용한다. 파일 오류는 숨기지 않는다.
- 원본 vs_popularity가 제공한 차이의 구간을 표시한다. 원본에 없는 구간은 생성하지 않는다.
- Amazon 주요 카드에 브랜드 일치도@12를 추가했다.
- 실제 원본 수치는 파일 확보 후 확인한다. 이번 자동 테스트는 형식을 재현한 fixture로 원본 우선·source별 fallback·파일 오류·구간 표시를 검증했다.
