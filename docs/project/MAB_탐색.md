# MAB 탐색 슬롯 · 신규 상품 노출 · 소분류 연속 제한 — 김광석

> 코드: `backend/app/services/explore.py`, 연결: `GET /recommend` (`routers/recommend.py`), 테스트: `backend/tests/test_explore.py`
> 파일럿: `simulator/catalog_pilot.py --arms ABC`, 화면: 대시보드 A/B 테스트 → 합성 A/B 탭 아래 "C · UME + MAB 탐색 슬롯"

명세 4.3 Stage 3 (Re-ranking) 중 세 가지를 맡는다.

| 명세 | 구현 |
|---|---|
| 상위 N개 중 1 ~ 2개는 MAB(ε-greedy 또는 UCB) 탐색 슬롯 | k ≥ 10이면 2개, 아니면 1개. UCB1 기본, ε-greedy 선택 가능. `is_exploration=true`, `reason="mab_exploration"` |
| 신규 상품(등록 7일 이내) 노출 기회 보장 | `items.registered_at`이 7일 안인 상품을 탐색 후보에 먼저 넣고, 노출 0이면 UCB 값이 무한대라 먼저 뽑힌다 |
| 같은 카테고리 상품 3개 이상 연속 금지 | 모든 추천(모든 모델)의 마지막 순서에서 같은 소분류가 3개째 이어지면 뒤에서 다른 소분류 상품을 당겨 온다 |

## 1. 흐름

```
추천 모델 (인기 · UME …) ─▶ 점수 순 k개
   └─▶ explore.apply
         1) params["explore"] 있으면: 후보 = 신규 상품(최대 100, 선호 소분류 것 먼저) + 선호 소분류 상품
            (목록 · 구매 상품 제외, 합계 최대 200, 그룹 안 순서는 고객 · 요청마다 섞음)
            → 상품별 (노출, 클릭) 집계 (비 setup 이벤트) → UCB1 / ε-greedy로
               슬롯 2개 = 신규 상품 1 + 선호 소분류 상품 1 (한쪽 후보가 없으면 다른 쪽에서)
            → 4 · 9번째 자리에 넣고 원래 목록은 그만큼 뒤에서 뺌
         2) 항상: 같은 소분류 3개 연속이면 뒤에서 다른 소분류 상품을 당겨 와 끊음
   └─▶ 응답 recommendations[] (탐색 상품: is_exploration=true · reason=mab_exploration · score_kind=rank)
```

- **팔(arm) = 상품.** 보상 = 노출(view) 뒤 클릭(click). 서비스에 이벤트가 쌓이면 다음 요청의 선택이 바뀐다 (따로 학습 단계 없음).
- **UCB1:** CTR + c · √(ln N / n), N = 후보 전체 노출, n = 그 상품 노출. 노출 0 → 무한대 (먼저 시도). 같은 값이면 신규 상품 먼저.
- **ε-greedy:** 확률 ε로 후보 중 무작위, 아니면 CTR 최고.
- **선호 소분류:** 고객의 구매 · 장바구니 · 클릭(초기 이력 포함) 상품 소분류 상위 3개. 이력이 없으면 신규 상품만 후보.
- **점수 표기:** 탐색 상품은 모델 점수가 없어 `score_kind="rank"`, `score_basis="rank_placeholder"` (응답 형식 변경 없음).
- **시간:** 탐색 · 연속 제한 시간은 `pipeline_latency.reranking_ms`에 더한다.

## 2. 켜는 법

탐색은 모델 버전마다 `params.explore`로 켠다 (없으면 끔 — 연속 제한만 적용). 같은 UME 가중치로 "탐색 없음 / 있음" 두 버전을 등록해 `/experiments`로 A/B 할 수 있다.

```json
{"explore": true}
{"explore": {"algorithm": "epsilon_greedy", "epsilon": 0.1, "slots": 2, "positions": [3, 8]}}
```

| 설정 | 기본값 | 뜻 |
|---|---|---|
| `algorithm` | `ucb` | `ucb` 또는 `epsilon_greedy` |
| `c` | 0.3 | UCB 탐색 강도. CTR이 0.1 안팎이라 UCB1 원형 c = 1은 보너스가 CTR 차이를 덮는다 — 팔 50개 · CTR 0 ~ 0.2 모의 실험 2,000회 뒤 상위 5개 상품 선택 비중 c = 1: 19%, c = 0.3: 63% (평균 CTR 0.12 → 0.16, seed 5개 평균) |
| `epsilon` | 0.1 | ε-greedy 무작위 비율 |
| `slots` · `min_k_two_slots` | 2 · 10 | k ≥ 10이면 2개, 아니면 1개 |
| `positions` | [3, 8] | 0부터 센 자리 (4 · 9번째) |
| `new_days` | 7 | 신규 상품 기준 일수 |
| `new_slots` | 1 | 슬롯 2개 중 신규 상품 몫 (슬롯 1개면 신규 우선) |
| `pool` · `preferred_categories` | 200 · 3 | 후보 최대 수(신규는 절반까지) · 선호 소분류 수 |

## 3. 신규 상품 (`items.registered_at`)

Amazon · H&M 공개 데이터에는 등록일이 없어 적재 상품은 `registered_at = NULL`(신규 아님)이다. 마이그레이션 `0002_item_registered_at`이 열만 추가하므로 기존 DB는 다시 적재할 필요가 없다 (api 재시작 시 Alembic이 자동 적용).

데모 · 확인용으로 일부 상품을 신규로 지정한다.

```bash
docker compose exec api python -m scripts.mark_new_items --count 200    # 무작위 200개를 최근 7일 안 등록으로
docker compose exec api python -m scripts.mark_new_items --clear         # 되돌리기
```

## 4. 파일럿 (C 그룹)

```bash
docker compose run --rm --no-deps \
  -v "$PWD/simulator:/app/simulator" -v "$PWD/recsys:/app/recsys:ro" \
  api python -m simulator.catalog_pilot \
    --customers 10000 --seed 42 --arms ABC --batches 10 --new-items 200 \
    --out /app/simulator/runs/catalog_pilot_abc_10k --api http://api:8000
```

- `--arms ABC`: A 인기 · B UME · C UME + 탐색 (고객을 페르소나 안에서 1/3씩). B와 C는 같은 UME 버전, C만 탐색을 켠다.
- `--batches 10`: 고객을 10묶음으로 나눠 묶음마다 행동을 재생하고 그 노출 · 클릭을 메모리 집계에 더해 다음 묶음의 탐색 선택에 쓴다 (서비스에서 이벤트가 쌓이며 배우는 흐름). 묶음별 탐색 CTR이 요약 `batches`에 남는다.
- `--new-items 200`: 이 실행 안에서만 200개를 신규 상품으로 지정 (끝에 rollback).
- `--explore-config '{"algorithm":"epsilon_greedy"}'`: C 그룹 설정 바꾸기.
- 요약 `comparisons`: `B_vs_A`(UME 효과) · `C_vs_B`(탐색 효과) · `C_vs_A`. `mab`: 탐색 슬롯 수 · 탐색 CTR vs 일반 슬롯 CTR · 신규 상품 노출.
- 모든 그룹에 `GET /recommend`와 같은 마지막 재정렬(연속 제한)을 적용하므로, A · B 숫자는 #50 결과와 조금 다를 수 있다.

## 5. 설계 중 바꾼 점 — 120명 파일럿

처음에는 탐색 슬롯 2개를 모두 "노출 0 · 신규 우선"으로 골랐다. 120명 (`--arms ABC --batches 3 --new-items 200`) 결과:
탐색 슬롯 80개가 모두 신규 상품, 그런데 서로 다른 상품은 **6개뿐**이고 탐색 CTR **0%** (C 그룹 일반 슬롯 3.1%).
동점(노출 0)일 때 등록 시각 순으로 골라 한 배치의 모든 고객이 같은 두 상품을 봤고, 신규 상품 200개가 고객 취향과
무관한 소분류라 클릭이 없었다. 그래서 (1) 슬롯을 신규 1 + 선호 소분류 1로 나누고 (2) 그룹 안 후보 순서를 고객 · 요청마다
섞고 (3) 신규 상품도 선호 소분류 것을 먼저 두도록 바꿨다.

## 6. 10,000명 결과 (2026-11-12, `catalog_pilot_abc_10k`)

`--customers 10000 --seed 42 --arms ABC --batches 10 --new-items 200`, 실행 68.8분 (고객당 0.41초, MacBook CPU).
요약 원본: [catalog_pilot_abc_10k_summary.json](catalog_pilot_abc_10k_summary.json). 주 지표는 첫 세션 고객 클릭률.

| 비교 | 대조 | 실험 | 차이 [95% 구간] | p |
|---|---:|---:|---:|---:|
| B(UME) − A(인기) | 34.9% | 36.3% | +1.4%p [−0.9, +3.7] | 0.23 |
| **C(UME + 탐색) − B(UME)** | 36.3% | 34.1% | **−2.2%p [−4.5, +0.1]** | 0.061 |
| C(UME + 탐색) − A(인기) | 34.9% | 34.1% | −0.8%p [−3.1, +1.5] | 0.51 |

그룹당 약 3,333명. 탐색 슬롯 지표:

| 항목 | 값 |
|---|---|
| 탐색 슬롯 | 6,666개 (C 고객 3,333명 × 2), 서로 다른 상품 3,291개 |
| 탐색 CTR vs C 일반 슬롯 CTR | **3.6%** (243 / 6,666) vs **4.8%** — 일반 슬롯의 약 75% |
| 신규 상품 노출 | 지정 200개 중 **199개** 노출, 탐색 슬롯 3,568회 (나머지 3,098회는 선호 소분류 상품) |
| 추천된 서로 다른 상품 수 | A 10 · B 3,080 · **C 6,016** (B의 약 2배) |
| 배치별 탐색 CTR (1 → 10) | 4.2 · 3.8 · 3.2 · 3.1 · 4.7 · 2.5 · 3.1 · 4.4 · 3.8 · 3.5% — 뚜렷한 증가 없음 |

페르소나별 C − B (다중 비교 미보정): 실용주의자 −6.0%p (p = 0.006), 가성비추구 −6.8%p (p = 0.005), 브랜드충성 −5.0%p (p = 0.12),
충동구매 +4.4%p (p = 0.24), 신중탐색 +1.3%p, 눈팅형 +1.0%p, 트렌드세터 0.0%p.

**해석.**

- **명세 요구(탐색 슬롯 1 ~ 2개 · 신규 상품 노출)는 충족한다.** 신규 상품 200개 중 199개가 한 번 이상 노출됐고, 다른 그룹에서는 5개만(원래 인기 · 개인화 순위에 있던 상품) 노출됐다.
- **비용: 첫 세션 클릭률 −2.2%p (유의 경계, p = 0.061).** 상위 10개 중 2자리를 UME 상위 9 · 10번째 대신 탐색 상품에 쓰기 때문이다. 탐색 상품 CTR은 일반 슬롯의 75% 수준이라 "아무 상품"보다는 훨씬 낫지만 개인화 상품보다는 낮다.
- **이득: 노출 다양성.** 서로 다른 추천 상품이 B의 약 2배(3,080 → 6,016)로 늘었다 — 명세 Coverage 지표와 신규 · 비인기 상품 노출 기회에 직접 기여한다.
- **페르소나:** 가격 · 적합도를 중시하는 실용주의자 · 가성비추구는 탐색 슬롯에서 손해가 크고, 새로움에 반응하는 충동구매 · 신중탐색 · 눈팅형은 손해가 없거나 작게 이득이다.
- **학습은 거의 보이지 않는다.** 팔이 상품 단위라 탐색 상품 3,291개가 평균 2회씩만 노출됐다. UCB가 CTR 차이를 구분하기에는 상품당 관측이 너무 적다 (모의 실험에서는 팔 50개 · 각 80회 정도에서 구분이 시작됨). 학습 효과를 보려면 팔을 소분류 · 후보 전략 단위로 묶거나 (예: "신규 · 선호 소분류 · 트렌딩" 중 어느 후보군을 쓸지 고르는 밴딧), Thompson Sampling처럼 사전분포를 쓰는 방식이 필요하다 — 다음 작업 후보.
- **운영 제안:** 탐색 슬롯을 모든 고객에게 2개씩 켜기보다 1개로 줄이거나(`slots: 1`), 실용주의 · 가성비 성향 고객에게는 줄이는 방식을 A/B로 비교할 만하다. 이 파일럿은 같은 명령에 `--explore-config '{"slots":1}'`로 다시 돌릴 수 있다.
- 모의 행동은 고객 × 순위 × 행동마다 같은 난수를 쓴다(공통 난수). 그래서 그룹 비교는 독립 표본보다 분산이 작고, 120명처럼 작은 표본에서는 특정 순위의 난수 때문에 결과가 크게 흔들린다 (120명 확인 실행에서 탐색 클릭 0회였던 이유).

## 7. 한계

- 탐색 CTR은 낮을 수 있다 — 탐색의 목적은 지금 클릭이 아니라 정보 수집 · 신규 상품 노출이다. 명세 과제 목표(Exploration vs Exploitation)는 C − B 클릭률 차이와 탐색 CTR의 묶음별 변화로 보고한다.
- 상품 단위 팔이라 상품이 많으면 대부분 노출 0에서 시작한다 (후보를 선호 소분류 · 200개로 제한하는 이유).
- 파일럿의 학습은 묶음 단위다 (묶음 안에서는 같은 통계). 서비스는 요청마다 DB 집계를 읽는다.
- Thompson Sampling은 보너스 과제로 남겨 둔다 (`algorithm` 값 추가로 확장).
