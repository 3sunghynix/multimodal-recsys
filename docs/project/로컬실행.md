
## 4. 전체 카탈로그 (상품 106,825개)

드라이브 `msrs_project/exports/msrs_full_catalog.zip`(2.1GB): 상품 106,825 · 브랜드 19,809 · 고객 232,644 · 이벤트 1,069,873 (train 최근 기간: H&M 4주 · Amazon 8주) · 이미지 106,818장, 3단계 카테고리 열 포함.

저장소가 OneDrive 안이면 풀어 둔 이미지(약 4GB)를 OneDrive가 동기화하려고 하므로 **저장소 밖에 푼다** (예: `C:\msrs_data\full_catalog`, zip 안 `data/full_catalog/` 아래 파일들). 그리고 저장소 루트에 로컬 전용 `docker-compose.override.yml`(git 제외 — `.git/info/exclude`에 추가):

```yaml
services:
  api:
    volumes:
      - C:/msrs_data/full_catalog:/data/full_catalog
    environment:
      IMAGES_ROOT: /data/full_catalog/images
```

```bash
docker compose up -d --build db api          # 대시보드까지: docker compose up -d --build (처음 빌드는 인터넷 필요)
docker compose exec api python -m scripts.load_dev_subset --data /data/full_catalog --embeddings /data/embeddings/v2 --reset
docker compose exec api python -m scripts.register_ume --activate
```

## 6. Feature Store (Redis)

명세 4.4 요구에 따라 Redis 를 사용자별 실시간 피처 저장소로 사용. docker-compose 에 추가됨 — `docker compose up -d` 한 줄로 같이 뜬다.

**저장되는 피처** (키: `u:{user_id}:...`)
- `recent_views` · `recent_clicks` — 최신 20개까지 LIST (LPUSH + LTRIM)
- `session_clicks` — 현재 세션 클릭 수 (TTL 30분, 비활동 시 자연 소멸)
- `last_activity` — 마지막 활동 시각

**쓰기:** `POST /events` 가 성공할 때마다 비동기로 반영. `is_setup=True` (초기 이력 적재) 는 Redis 에도 안 씀 (집계 제외 규칙 일관).

**읽기:** `GET /recommend/{user_id}` 응답의 `session_context.recent_clicks` 가 **Redis 우선** 으로 읽음. Redis 가 없거나 cold 이면 **DB 쿼리로 자동 폴백** — 기존 동작 그대로.

**가용성:** `REDIS_URL` 비어 있거나 Redis 다운이면 전체 **no-op**. 서버는 계속 뜨고, DB 폴백만으로 작동. 로컬 테스트(pytest)도 Redis 없이 돈다.

**측정 (명세 요구 ≤ 10ms)**
```bash
curl http://localhost:8000/features/latency
# → {"redis":true,"ping_ms":0.48,"within_spec":true,"limit_ms":10}
```
Redis 꺼지면 `{"redis":false,"reason":"..."}`.
