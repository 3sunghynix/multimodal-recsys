# 광석 개발·발표 학습 기록

## 2026-10-29 — PR #22 평가 리뷰 반영

### 이번에 해결한 문제

기존 main에 이미 빠른 오프라인 평가 모듈이 있는데, 별도 evaluation 패키지를 추가하면 운영 지표 정의가 두 벌이 된다. 기존 코드를 대표 구현으로 유지하고 내 계산은 읽기 쉬운 기준 구현으로 옮겨 교차 검사하도록 정리했다.

### 코드의 역할

- `recsys/eval/metrics.py`: 모델 실험에서 사용하는 기존 빠른 지표 계산. 변경하지 않았다.
- `recsys/run_eval.py`: 고정 분할·정답·평가 고객을 만드는 기존 실행 진입점. 변경하지 않았다.
- `recsys/eval/reference.py`: 독립 공식으로 정답을 확인하는 느린 기준 구현. 운영 CLI가 아니다.
- `recsys/eval/online.py`: 지정 이벤트 유형·기간의 고객별 최다 브랜드 비중 평균. DB·전송 중복 제거는 호출자가 처리한다.
- `recsys/tests/test_reference_compatibility.py`: 같은 입력에서 빠른 구현과 기준 구현이 일치하는지 확인한다.
- `recsys/tests/test_reference_online.py`: 손계산·누락·중복·벡터 오류·온라인 브랜드 비중 검사.

### 쉬운 설명

- Recall: 실제 정답 중 몇 개를 찾았는가.
- NDCG: 정답을 목록 위쪽에 놓았는가.
- MAP: 정답이 등장한 위치의 정밀도를 평균한다. 분모는 min(K, 정답 수)다.
- 커버리지: 고정 카탈로그 중 추천에 등장한 서로 다른 상품의 비율.
- 다양성: 한 목록에서 상품 벡터끼리 얼마나 다른가. 코사인 거리는 0~2다.
- 최다 브랜드 비중: 고객 행동이 한 브랜드에 얼마나 집중되는가. 높을수록 무조건 좋다는 지표가 아니다.

### 손으로 확인하는 예제

정답 {A,B}, 추천 [A,X,B], K=3이면 Recall=1, AP=(1+2/3)/2=5/6이다. 추천이 [A,B,X]가 되면 Recall은 그대로지만 AP와 NDCG는 1이 된다.

고객 A가 1개 중 1개, B가 3개 중 0개를 맞히면 고객별 평균 Recall은 50%지만 구매 단위 적중률은 25%다. 이 둘을 섞으면 안 된다.

### 검증 범위

- 최신 확인 main e2c657b(#19 평가·기준선, #20 통합 검색)와 결합한 로컬 사본에서 recsys 테스트 37개 통과.
- 정확도·커버리지·다양성 및 알려진 브랜드의 고객별 비중을 동일 입력으로 교차 검사했다.
- 원래의 가상 예제 결과는 Recall=0.5, MAP≈0.416667, 다양성≈0.666667이다. 실제 모델 성능이 아니다.
- 0벡터는 기존 fast 다양성에서 유사도 0, reference에서 오류다. 공통 유효 입력에서는 일치하며 경계 정책 차이는 지표 문서에 명시했다.
- 실제 공유 데이터 평가·DB·Docker·화면 연동·통계적 A/B 판정은 이번 검증 범위가 아니다.
