## 개정 요약 (2026-09-29)

사전 등록한 주 가설("이미지 기여는 패턴 상품에서 더 크다")은 **지지되지 않았다**. 대신 이미지 기여 자체가 크고, 그 크기가
**인코더에 따라 크게 달라진다**는 결과가 모든 강건성 확인에서 일관되게 나왔다. 논문은 이 결과를 중심으로 쓰고,
주 가설의 불지지는 사전 등록 결과로 그대로 보고한다. 결과를 본 뒤 추가한 분석은 모두 **탐색적**으로 표시한다.

## 1. 논문의 주장 (새 방향)

> 패션 추천에서 이미지는 도움이 된다. 단, 인코더에 달렸다. 패션 전용 인코더(Marqo-FashionSigLIP)는 텍스트 대비
> Recall@300을 +14% (신규 상품 +46%) 올리고, 이미지만으로도 텍스트를 넘으며, 그 효과는 품목 정보가 아니라 세밀한 시각
> 정보에서 온다. 구세대 인코더(ResNet-50)에서는 효과가 약 1/3이다. 이미지 효과가 패턴 상품에 몰린다는 가설은 지지되지 않았다.

| 질문 | 성격 | 결과 |
|---|---|---|
| 같은 상품군 안에서 이미지 기여가 패턴 > 무지인가 (주 검정) | 사전 등록 | **불지지**: +0.0018 [−0.0009, +0.0051] |
| 이미지는 텍스트 위에 추가로 도움이 되는가 | 탐색적 | Marqo +0.0128 [0.0113, 0.0142], 모든 조건에서 구간 > 0 |
| 인코더에 따라 달라지는가 | 탐색적 (RQ2 확장) | Marqo +0.0128 > CLIP +0.0076 > ResNet +0.0048, 구간 겹치지 않음 |
| 효과는 품목 정보인가 세밀한 시각 정보인가 | 탐색적 | 같은 품목 안 섞기(+0.0155) ≈ 전체 섞기(+0.0165) → 세밀한 정보 |
| 신규 상품에서 더 큰가 (H4) | 사전 등록 보조 | 방향 일치: +0.0234 (상대 +46%) |

## 2. 강건성 확인 (모두 완료)

| 확인 | 결과 |
|---|---|
| seed 3개 (주 조건, 인코더 비교) | 조건 간 차이가 seed 표준편차(약 0.003)보다 큼 |
| 다른 테스트 주 (alt) | Marqo 이미지 효과 +0.0166로 재현 |

| 섞은 이미지 대조군 | 섞으면 텍스트만보다도 낮아짐 → 모델이 이미지 내용을 실제로 사용 |

## 3. 남은 약점과 보완 계획

- **단순 베이스라인에 크게 짐:** 재구매 + 인기 0.257, 직전 1주 인기 0.230 vs 텍스트 + Marqo 0.106. 인기도 입력으로도 해결되지 않음
  (원인 추정: 배치 내 부정 샘플 학습이 인기 상품을 억누름. logQ 보정이 알려진 해법).
- **보완 (다음 작업, 탐색적):** 결합 후보 분석. "재구매 + 인기" 후보에 모델 후보를 합쳤을 때, 이미지가 추가로 맞히는 구매를 측정한다.
  재학습 없이 기존 후보 파일로 계산하고, 프로젝트의 Multi-Stage(여러 출처 후보 → 순위) 구조와 맞는다.
- logQ 보정 재학습은 사후 변경이 쌓이므로 하지 않는다. 한계 절에 적는다.

# 부록 A. 사전 등록 원안 (2026-09-28 작성, 결과 확인 전. 아래 내용은 수정하지 않는다)

> 원래 제목: 패션 추천에서 이미지는 어떤 상품에 도움이 되는가? — H&M 실구매 데이터로 본 상품 유형별 이미지 기여도 분석

## 0. 한 줄 요약

텍스트 대비 이미지가 더해주는 추천 성능이 **같은 상품군 안에서** 패턴·프린트 상품과 무지 상품 사이에 다른지를, 프로젝트의 Two-Tower 모델과 두 가지 섞은 임베딩 대조군으로 측정한다. 주장의 근거는 결과 보기 전에 정한 검정 하나다 (7.7절).

---

## 1. 연구 질문과 가설

| 구분 | 질문 |
|---|---|
| **RQ1 (주)** | 같은 상품군 안에서, 텍스트 대비 이미지가 더해주는 성능은 패턴·프린트 상품과 무지 상품 사이에 다른가? 그 차이는 카테고리 수준을 넘어선 세밀한 시각 정보(패턴, 디자인)에서 오는가? |
| **RQ2 (보조)** | 패션 전용 인코더를 쓰면 이 차이가 더 커지는가? 인코더의 패턴 인식 능력(DeepFashion)과 관련이 있는가? |
| **RQ3 (보조)** | 재구매가 아닌 구매와 신규 상품에서 이미지 기여도가 더 큰가? |

**가설**
- H1: 같은 상품군 안에서 이미지 기여도는 패턴·프린트 상품 > 무지 상품이다.
- H2: 그 차이는 같은 카테고리 안에서 섞은 대조군과 비교해도 남는다 (세밀한 시각 정보의 기여).
- H3: 패션 전용 인코더에서 H1의 차이가 가장 크고, DeepFashion 패턴 속성 분류 정확도와 같은 순서를 보인다.
- H4: 이미지 기여도는 신규 상품 구간에서 가장 크다.

## 2. 배경과 기여

**배경**
- 업계에서는 이미지 기반 유사 상품·검색 기능의 효과가 실서비스 실험으로 보고되었다. (Pinterest, Alibaba, Mercari) 【확인 필요】
- 반면 최근 학계 연구(Ye 외 2025)는 Amazon Clothing 등에서 이미지를 빼도 대부분 모델의 성능 하락이 5% 미만이라고 보고했다. 이 연구의 이미지 특징은 ResNet-50 고정 벡터 하나였다. 【확인 필요: 원문 표】
- 인코더를 바꿨을 때 추천 성능이 어떻게 변하는지는 이미 여러 연구가 다뤘다. (MoRec 2023, VIP5 2023, Ducho 벤치마크 2025) 【확인 필요】
- 고객별로 모달리티 가중치를 다르게 주는 방식은 전역 가중치 대비 이득이 거의 없다는 보고가 있다. (2026) 【확인 필요】

**우리의 기여 (주장 전 반드시 확인: 8절 인용 확인 목록)**
1. 이미지 기여도를 전체 평균이 아니라 **상품 유형별로, 같은 상품군 안에서 층화하여** 측정한 첫 분석.
2. **두 가지 섞은 임베딩 대조군**(전체 섞기, 같은 카테고리 안에서 섞기)으로 "이미지 내용"과 "카테고리를 넘어선 세밀한 시각 정보"의 기여를 분리.
3. 최신 패션 전용 인코더(Marqo-FashionSigLIP)를 실구매 기반 추천에서 평가하고, 인코더의 패턴 인식 능력(DeepFashion)과 연결.

**차별점**: 인코더 세대 비교 자체는 주 기여가 아니다(선행 연구 존재). 주 기여는 "어떤 상품에서"와 "어떤 시각 정보가"이다.

## 4. 상품 유형 분류

분류 모델을 만들지 않는다. `articles.csv` 메타데이터를 **결과를 보기 전에** 정한 규칙으로 묶는다. 매핑 표는 1일차에 설정 파일로 레포에 커밋하고 이후 바꾸지 않는다 (7.7절).

### 4.1 축 1 (주): 외관 패턴 — `graphical_appearance_name`

| 그룹 | 포함 값 (1일차 실제 값 확인 후 확정) |
|---|---|
| 무지 | Solid |
| 패턴·프린트 | Stripe, Check, Dot, All over pattern, Front print, Placement print, Colour blocking, Embroidery, Argyle, Other pattern, Mixed solid/pattern |
| 질감·소재 | Denim, Melange, Lace, Jacquard, Mesh, Chambray, Glittering/Metallic, Sequin, Transparent, Other structure |
| 제외 | Unknown |

### 4.2 축 2 (층화 기준): 상품군 — `product_group_name`

상의 / 하의 / 원피스·전신 / 신발 / 액세서리 / 기타(속옷·잠옷·양말 합침)

- **패턴 대 무지 비교는 반드시 같은 상품군 안에서 한다.** (7.3절)
- 패턴 상품이 상의·원피스에, 무지 상품이 양말·속옷·기본템에 몰려 있으면, 층화 없이 나온 차이는 카테고리 차이일 수 있기 때문이다.

### 4.3 축 3 (리스크 대응): 설명에 패턴 언급 여부 — `detail_desc`

- 패턴 관련 단어(stripe, print, check, pattern, dot, floral, logo, graphic, motif 등) 포함 여부로 나눈다. 단어 목록도 1일차에 확정.
- 축 1과 교차해 "설명에 패턴이 적히지 않은 패턴 상품"을 따로 본다.

### 4.4 품질 확인

- 그룹마다 이미지 30~50장을 눈으로 확인해 라벨 일치율을 기록한다 (논문에 한 줄).
- 그룹별 테스트 구매 수를 기록한다. 너무 적은 셀(기준 【미정】, 예: 300건 미만)은 합치거나 제외한다.

## 5. 인코더와 입력

| 구분 | 모델 | 역할 |
|---|---|---|
| 텍스트 | all-MiniLM-L6-v2 (고정) | Ye 외와 같은 기준 |
| 이미지 | ResNet-50 (ImageNet) | Ye 외와 같은 기준 (구세대) |
| 이미지 | CLIP ViT-B/32 | 범용 최신 |
| 이미지 | Marqo-FashionSigLIP | 패션 전용 |

- 텍스트 입력: `prod_name` + `product_type_name` + `colour_group_name` + `detail_desc`.
- 모든 임베딩은 PCA로 같은 차원(【미정】, 예: 256)으로 맞춘다. 인코더 간 공정 비교.
  - PCA는 전체 상품 카탈로그로 학습한다. 구매 정보를 쓰지 않으므로 테스트 정보가 새지 않는다.
  - PCA 후 각 벡터를 L2 정규화해서 텍스트와 이미지의 크기를 맞춘다. 한쪽 크기가 크면 모델이 그쪽만 쓰는 불균형이 생긴다.
  - 이미지가 없는 상품은 후보에서 제외하고 그 수를 기록한다.
- 임베딩은 한 번 추출해 파일(`.npy`)로 저장하고 팀이 공유한다. 레포에는 올리지 않는다.

## 6. 모델 (프로젝트 코드 재사용)

- **주 모델: Two-Tower (추천 1단계)**
  - 상품 타워는 **ID 없이 임베딩만** 입력한다. 모델이 콘텐츠를 쓸 수밖에 없고, 처음 보는 신규 상품도 점수를 매길 수 있다.
  - 고객 타워는 학습 기간 구매 상품 시퀀스를 입력으로 한다 (프로젝트 설계를 따른다).
- **교차 확인용 (학습 없음)**: 고객이 산 상품 임베딩의 평균과 가까운 상품 추천. 텍스트만 / 텍스트 + 최고 인코더 두 조건만.
- **DeepFM (추천 2단계)**: 결과는 프로젝트 `docs/` 리포트에만 넣는다.
- **베이스라인**: 최근 1주 인기 상품, 재구매 + 인기 상품 (고객이 산 상품을 최근 순으로 넣고 나머지 자리를 인기 상품으로 채워 300개).
- **튜닝 규칙**: 모든 조건에 같은 튜닝 예산을 쓴다. 학습률·임베딩 크기 등 후보 조합을 미리 정하고(【미정】), 검증 주 Recall@300으로 고른다. 텍스트만 조건에 유리한 설정을 고른 뒤 다른 조건에 그대로 쓰는 방식은 피한다.
- **고객 타워 주의**: 고객 타워가 구매 상품의 임베딩을 입력으로 쓰면, 이미지 조건은 양쪽 타워에 모두 영향을 준다. 섞은 대조군도 양쪽에 같은 대응표를 적용한다 (7.1).

## 7. 실험 설계와 평가

### 7.1 입력 조건과 대조군 (13개 조건, 주 조건 4개는 seed 3개 → Two-Tower 학습 총 21회)

| 조건 | 개수 |
|---|---|
| 텍스트만 (T) | 1 |
| 인코더별: 이미지만 (I) | 3 |
| 인코더별: 텍스트 + 이미지 (T+I) | 3 |
| 인코더별: 텍스트 + **전체에서 섞은** 이미지 (T+I_shuf) | 3 |
| 인코더별: 텍스트 + **같은 `product_type_name` 안에서 섞은** 이미지 (T+I_shufcat) | 3 |

섞기: 상품마다 다른 상품의 이미지 임베딩을 무작위로 배정한다. 같은 카테고리 안에서 섞으면 이미지에 담긴 대략적인 카테고리 정보는 유지되고, 세밀한 시각 정보만 사라진다.

**섞기 구현 규칙**
- 섞기는 "상품 → 이미지 임베딩" 대응표 하나를 만들어 학습·검증·테스트와 고객 타워·상품 타워 전체에 **똑같이** 적용한다. 단계나 타워마다 다르게 섞으면 대조군이 아니라 잡음이 된다.
- 대응표는 seed로 고정하고 파일로 저장한다.
- 같은 카테고리 안에서 섞을 때 상품이 1개뿐인 `product_type_name`은 섞을 수 없으므로 해당 상품 목록과 비율을 기록한다.

### 7.2 측정값 정의

| 이름 | 정의 | 의미 |
|---|---|---|
| 이미지 기여도 Δ_img | R(T+I) − R(T) | 텍스트 대비 이미지가 더해주는 성능 |
| 내용 기여도 Δ_content | R(T+I) − R(T+I_shuf) | 모델이 이미지 내용을 실제로 쓴 정도 (0보다 커야 함) |
| 세밀 기여도 Δ_fine | R(T+I) − R(T+I_shufcat) | 카테고리를 넘어선 패턴·디자인 정보의 기여 (**RQ1의 핵심**) |

R = Recall@300 (주 지표).

**입력 차원 주의**: 결합은 이어 붙이기([T; I])라서 T+I 입력(512차원)이 T 입력(256차원)보다 크다. 그래서 Δ_img에는 "입력이 커져서 생긴 효과"가 섞일 수 있다. 섞은 대조군은 T+I와 입력 크기가 같으므로 **Δ_content와 Δ_fine이 이 효과를 통제한 값**이다. 논문의 주장은 Δ_fine과 Δ_content로 하고, Δ_img는 서술용으로만 쓴다.

### 7.3 층화 분석 (방법론상 가장 중요)

- 각 테스트 구매를 산 상품의 (상품군, 외관 그룹) 셀에 배정한다. 추천은 전체 상품 대상으로 똑같이 하고, 채점만 셀별로 나눈다.
- 상품군 g 안에서: D_g = Δ(패턴·프린트, g) − Δ(무지, g)
- 전체 효과: 셀의 테스트 구매 수로 가중 평균한 D. 상품군별 D_g도 함께 보고한다.
- 층화 없는 단순 비교는 참고용으로만 부록 또는 리포트에 둔다.

### 7.4 평가 구간과 지표

- 구간: ① 전체 구매 ② 재구매가 아닌 구매 (고객이 처음 사는 상품) ③ 신규 상품 (테스트 주에 처음 팔린 상품)
  - ②의 "예전에 산 적 없음"과 ③의 "처음 팔림"은 6개월 학습 기간이 아니라 **2018년부터의 전체 구매 기록** 기준으로 판정한다. 6개월 이전에 팔린 상품이 신규로 잘못 분류되는 것을 막기 위해서다.
- 주 지표: **Recall@300** (차터의 후보 생성 지표). 보조 지표: NDCG@12.
  - 후보가 약 10만 개이고 ID 없는 모델이라 NDCG@12가 0.00x 수준으로 작아 잡음에 묻힐 수 있다.
- 모든 지표는 `src/evaluation/metrics.py`로만 산출한다.

**채점 방식**
- 테스트 고객 = 필터를 통과하고 테스트 주에 1건 이상 산 고객. 같은 상품을 여러 번 산 경우 1건으로 센다.
- 추천 목록은 전체 상품 대상 상위 300개. 예전에 산 상품도 목록에서 빼지 않는다 (모든 조건 동일).
- 구간 ② ③은 채점 대상 구매만 해당 구간으로 제한하고, 추천 목록은 그대로 쓴다. 해당 구간 구매가 없는 고객은 그 구간 평균에서 제외한다.

**평균 내는 방식 (두 가지를 용도별로 구분)**

| 용도 | 방식 | 계산 |
|---|---|---|
| 표 1 (전체 성능) | **고객별 평균** | 고객마다 (맞힌 구매 수 / 그 고객의 구매 수)를 구해 평균 |
| 그림 1 (상품 유형별, 7.3) | **구매 건별 비율** | 그 셀에 속한 테스트 구매 중 추천 300개 안에 든 비율. 셀마다 고객 수가 크게 달라도 안정적 |

예시: 고객 A가 4개를 사고 그중 2개가 추천 300개 안에 있으면 고객 A의 Recall@300 = 0.5.

### 7.5 색상 변형 대응 (`product_code` 수준 평가)

- H&M은 같은 `product_code` 아래 색상만 다른 `article_id`가 여러 개이고 설명이 거의 같다. 이미지 기여도가 "색상 구분 효과"로 부풀려질 수 있다.
- 텍스트에 `colour_group_name`을 넣어 1차 대응한다.
- 추가 분석: 추천 목록과 정답을 `product_code`로 바꿔(중복 제거) 다시 채점한다. 이 수준에서도 Δ가 남으면 색상 구분만의 효과가 아니다.
- 결과와 무관하게 한계 절에 이 문제를 명시한다.

### 7.6 통계

- 신뢰구간: **테스트 고객 단위 부트스트랩** (1,000회, 95%).
- 조건 간 차이(Δ, D)는 **같은 고객 표본으로 짝지은(paired) 부트스트랩**으로 구한다.
- 테스트 주 반복(3~4주)은 신뢰구간이 아니라 "주마다 결론이 일관된가" 확인용이다.
- 모든 표에 셀별 표본 수(테스트 구매 수, 고객 수)를 함께 보고한다.
- **학습 seed 반복 (필수)**: 부트스트랩은 고객 표본의 흔들림만 반영하고, 모델 학습의 무작위성은 반영하지 못한다. 기대하는 차이가 0.01 수준으로 작아서 학습 seed에 따른 흔들림이 더 클 수 있다.
  - 주 가설에 쓰는 조건(T, Marqo 인코더의 T+I · T+I_shuf · T+I_shufcat)은 seed 3개(42, 43, 44)로 학습하고 평균과 범위를 보고한다.
  - 나머지 조건은 seed 42 한 번. 시간이 되면 추가.
  - 섞기 대응표도 seed마다 새로 만든다.

### 7.7 사전 등록: 주 가설 검정 하나

셀 수(상품군 6 × 외관 3) × 인코더 3 × 구간 3으로 비교가 많아 우연히 유의한 결과가 나올 수 있다. 그래서 **주장의 근거가 되는 검정 하나를 결과 보기 전에 정해 둔다.**

- **주 검정**: 인코더 Marqo-FashionSigLIP, 구간 ② 재구매가 아닌 구매, 측정값 Δ_fine으로 계산한 상품군 가중 평균 D (패턴·프린트 − 무지). 짝지은 부트스트랩 95% 구간이 0보다 크면 H1·H2를 지지한다.
- 나머지 비교(다른 인코더, 다른 구간, 상품군별 D_g, 질감·소재 그룹)는 **탐색적 분석**으로 표시하고 결론의 근거로 쓰지 않는다.
- 이 계획서의 커밋 날짜가 사전 등록 기록이 된다. 코드가 같은 기준을 쓰도록 주 검정 정의와 4절 매핑 표는 **설정 파일(예: `configs/analysis_plan.yaml`)로도 만들어 1일차에 커밋**한다.

### 7.8 DeepFashion 연결 (RQ2)

- DeepFashion 속성 중 질감·패턴 속성을 4.1절 그룹 기준에 맞춰 묶는다.
- 인코더 3종 임베딩으로 선형 분류기(logistic regression)를 학습해 패턴 속성 분류 정확도를 잰다.
- 이 정확도 순서와 H&M의 D(패턴 대 무지 기여도 차이) 순서를 비교한다. 인코더가 3개뿐이므로 상관계수가 아니라 순서 일치로만 서술한다.

| 모델이 베이스라인에 짐 | 주장은 기여도 비교. 파일럿 기준 완화, 한계 절 명시 (9) |

## 13. 피드백 반영 기록

| 피드백 | 반영 |
|---|---|
| 실험 규모가 3쪽에 비해 큼, 프로젝트와 연결 약함 | 인코더 6종 → 3종, MMRec → 프로젝트 Two-Tower, 결과물은 논문(핵심) + 리포트(전체)로 분리 |
| VBPR은 이미지를 안 써서 결과를 오염시킴 | VBPR 제외, ID 없는 Two-Tower + 섞은 대조군 |
| MMRec 5-core 필터로 신규 상품이 평가에서 빠짐 | 고객에게만 필터, 전체 상품을 후보로 |
| 단순 베이스라인에 질 수 있음 | 재구매 + 인기 베이스라인, 재구매가 아닌 구매 구간 |
| 인코더 세대 비교는 이미 연구됨 | RQ1을 상품 유형별 분석으로 교체, 인코더는 보조 |
| 필수 데이터셋 3종 | H&M 주 데이터, DeepFashion은 RQ2 probe, Retailrocket은 프로젝트 전용 |
| 패턴 대 무지 = 카테고리 차이일 수 있음 | 같은 상품군 안 층화 비교 (7.3) |
| 색상 변형 문제 | `product_code` 수준 평가, 한계 명시 (7.5) |
| 테스트 주 3~4개로는 신뢰구간 무의미 | 고객 단위 짝지은 부트스트랩, 주 반복은 일관성 확인용 (7.6) |
| 전체 섞기는 카테고리 정보까지 지움 | 같은 카테고리 안 섞기 대조군 추가, Δ_fine 정의 (7.1, 7.2) |
| NDCG@12가 잡음에 묻힘 | Recall@300 주 지표 (7.4) |
| 파일럿 첫 기준이 너무 어려움 | 기준 완화, 섞은 대조군을 1순위 기준으로 (9) |
| 원문 확인 전 인용 금지 | 인용 확인 목록, Pomo 외를 09.30까지 (8) |
| 추천 성능 채점 방식 명확화 | 표 1은 고객별 평균, 그림 1은 구매 건별 비율, 채점 규칙 명시 (7.4) |
| (자체 검토) 결합 시 입력 차원 효과 | Δ_img는 서술용, 주장은 Δ_content · Δ_fine (7.2) |
| (자체 검토) 다중 비교 | 주 검정 사전 등록 (7.7) |
| (자체 검토) 부트스트랩은 학습 무작위성을 반영 못 함 | 주 조건 seed 3개 필수 (7.6) |
| (자체 검토) 섞기가 단계·타워마다 다르면 무효 | 대응표 하나를 전체에 적용 (7.1, 6) |
| (자체 검토) 신규·재구매 판정 기준 | 전체 구매 기록 기준 (7.4) |
| (자체 검토) 튜닝 공정성, 텍스트·이미지 크기 불균형 | 같은 튜닝 예산, L2 정규화 (5, 6) |
