## 0. 실행 전 명확화 (사전 등록 해석, 설계 변경 아님)

사전 등록에 해석이 필요한 부분 하나를 **학습 실행 전에** 별도 커밋으로 확정한다.

| 항목 | 사전 등록 문구 | 확정할 해석 | 이유 |
|---|---|---|---|
| "10회 이상 팔린 상품" | 최종 학습 기간(검증 주 포함)에 10회 이상 팔린 상품 | **학습에 실제로 쓰는 데이터**(구매 5회 이상 고객의 학습 + 검증 기간 구매)에서 센 판매 횟수 | 이 구간의 목적은 "ID 임베딩이 충분히 학습된 상품"이다. ID 임베딩은 학습 데이터로만 학습되므로 같은 데이터로 센다 |

같은 기준으로 "최종 학습 기간에 한 번도 팔리지 않은 상품"(ID 0 처리 대상)도 학습 데이터 기준으로 센다.

## 1. 코드 추가 (파일별)

| 파일 | 추가 내용 | 확인 방법 |
|---|---|---|
| `configs/paper.yaml` | 이미지 인코더 3종 등록: `siglip_b16`(open_clip `ViT-B-16-SigLIP`, `webli`), `laion_b32`(open_clip `ViT-B-32`, `laion2b_s34b_b79k`), `fashionclip2`(Hugging Face `patrickjohncyh/fashion-clip`). ID 튜닝 후보 i1~i4, `id_selected`(튜닝 후 기입), `id_tuned: false` | 설정 불러오기 테스트 |
| `msrs_paper/embeddings.py` | Hugging Face CLIP 모델 불러오기(`fashionclip2`용). **추출 시 모델 구조 이름을 임베딩 정보 파일(`.json`)에 기록** | 쌍끼리 구조 이름이 같은지 자동 확인 |
| `configs/experiments.yaml` | 새 조건과 묶음 (아래 2절 표) | 조건 수 자동 집계 = 사전 등록과 일치 |
| `msrs_paper/two_tower.py` | 상품 ID 임베딩: 상품 타워 입력 = 콘텐츠 ⊕ ID. 학습 데이터에 없는 상품의 ID는 항상 0. ID 드롭아웃(학습 중 확률 p로 ID 부분을 0으로). 고객 타워는 그대로 | ① 신규 상품 ID가 0인지 ② 드롭아웃 0이면 기존과 같은 경로인지 ③ ID 끈 조건의 결과가 기존 코드와 **완전히 같은지** |
| `msrs_paper/metrics.py` | 구간 추가: `established`(학습 데이터 판매 10회 이상), `sparse`(1~9회), 민감도용 기준 5 · 20회 | 합성 데이터로 구간 크기 손 계산과 비교 |
| `msrs_paper/analysis_v2.py` (새 파일) | 사전 등록 파일을 읽어 실행: 상대 기여도(분자·분모 같은 구간), H1 · H2 차이와 **97.5%** 짝지은 부트스트랩 구간, 재현 쌍 방향 확인, 탐색적 분석, 표 · 그림 | 합성 데이터에서 독립 재계산과 일치 |
| `notebooks/07_prereg_v2.ipynb` (새 노트북) | 2~5단계를 한 노트북에서 순서대로. 단계마다 확인 셀 포함 | 셀 문법 검사 |

**불변 원칙:** 기존 묶음 A~D의 결과가 바뀌면 안 된다. ID를 끈 조건은 코드 수정 전후로 추천 결과가 완전히 같아야 한다 (1차 때와 같은 방식으로 확인).

## 2. 실행할 묶음

| 묶음 | 목적 | 조건 | seed | 횟수 |
|---|---|---|---|---|
| **E** | H1 · 재현 쌍 (ID 없음, 새 인코더) | 범용 SigLIP · FashionCLIP 2.0 · LAION CLIP 각각 × {텍스트 + 이미지, + 전체 섞기, + 같은 품목 안 섞기} | 42 · 43 · 44 | 27 |
| **튜닝** | ID 설정 선택 | ID 있는 Marqo 텍스트 + 이미지 × i1~i4 (검증 주) | 42 | 4 |
| **F** | H2 (ID 있음, 선택 설정) | 텍스트만 + Marqo × 3 + 범용 SigLIP × 3 | 42 · 43 · 44 | 21 |
| **G** | 드롭아웃 0(i2) 민감도 | F와 같은 조건, 설정만 i2 (선택 설정이 i2면 생략) | 42 · 43 · 44 | 최대 21 |
| 재사용 | ID 없음 텍스트만(C0), Marqo(C2 · C3 · C4) | 기존 묶음 A 결과 | 42 · 43 · 44 | 0 |

- 합계: 27 + 4 + 21 + 최대 21 = **최대 73회**. 1회 약 20초 + 불러오기.
- 모든 묶음은 **한 사람이 한 Colab 세션(L4)에서** 돌린다. 기존 묶음 A도 L4에서 돌렸다.

## 3. 실행 순서 (07 노트북)

| 셀 | 내용 | 확인할 것 |
|---|---|---|
| 0 | 공통 준비 (새 런타임 필수) | 코드 커밋 번호, GPU = L4 |
| 1 | 사전 등록 · 설정 확인 | `prereg_v2.yaml` status final, 명확화 커밋 포함 |
| 2 | 임베딩 3종 추출 → PCA 256 → L2 정규화 | 쌍별 구조 이름 일치 (`ViT-B-16-SigLIP` 둘, `ViT-B-32` 둘), NaN 없음, 최근접 이웃 격자 |
| 3 | 섞기 대응표는 기존 것을 그대로 사용 (상품 순서 동일) | 상품 수 53,232 일치 |
| 4 | 체크섬 목록 갱신 | 기존 20개 + 새 임베딩 파일 |
| 5 | 묶음 E 학습 | 27회 완료 |
| 6 | ID 튜닝 i1~i4 | 검증 Recall@300 표 → **1등 설정을 `paper.yaml`에 적고 `id_tuned: true`로 커밋** (1차 튜닝과 같은 방식) |
| 7 | 새 런타임에서 셀 0부터 다시 → 묶음 F, G | 21회 + 최대 21회 |
| 8 | `analysis_v2` 실행 | H1 · H2 판정, 재현 쌍 방향, 표 · 그림 |

셀 6에서 설정을 커밋한 뒤에는 **반드시 새 런타임**으로 셀 0부터 다시 실행한다 (옛 코드가 메모리에 남는 사고 방지).

## 5. 품질 확인 체크리스트

- [ ] 명확화 커밋이 학습 실행보다 먼저다 (커밋 시각으로 확인)
- [ ] ID를 끈 조건의 결과가 코드 수정 전후로 완전히 같다
- [ ] 신규 상품의 ID 임베딩이 예측 때 0이다
- [ ] 쌍별 구조 이름이 같다
- [ ] 합성 데이터에서 상대 기여도와 H1 · H2 차이를 독립 재계산과 비교해 일치한다
- [ ] ID 튜닝 결과와 선택 설정이 본 학습 전에 커밋됐다
- [ ] 모든 묶음이 같은 GPU 종류(L4)에서 새 런타임으로 실행됐다
- [ ] 결과와 관계없이 `confirmatory.json`을 그대로 보고한다

## 6. 멈춰야 하는 경우

| 상황 | 대응 |
|---|---|
| 쌍의 구조 이름이 다르게 나옴 | 실행 중단, 모델 출처 재확인 후 사전 등록 수정 여부를 팀과 결정 (실행 전) |
| ID 모델 검증 Recall이 ID 없는 모델보다 크게 낮음 | 구현 오류 가능성. 합성 데이터로 재점검. 설정을 바꾸려면 실행 전 사전 등록 수정 절차 |
| 기존 상품 구간의 테스트 구매가 너무 적음 | 그대로 진행하고 구간 크기를 보고 (기준은 이미 등록됨) |
| 코드 수정 후 ID 끈 결과가 기존과 달라짐 | 실행 중단, 원인 찾을 때까지 진행하지 않음 |
