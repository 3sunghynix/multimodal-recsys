# 가설별 실험 가이드: 텍스트 + 이미지에서 이미지는 언제 · 어디서 · 어떻게 도움이 되는가

> 3성하이닉스 팀 공유용 · 2026-10-12 · 작성 김유환
> 근거: [실험기록.md](실험기록.md) (모든 수치의 출처) · [주제재검토.md](주제재검토.md) · 사전 등록 [`analysis_plan.yaml`](../paper/configs/analysis_plan.yaml), [`prereg_v2.yaml`](../paper/configs/prereg_v2.yaml)
> **사용법:** 1절(공통 설정)과 2절(진행 규칙)을 먼저 읽고, 3절에서 지금까지의 결과를, 4절에서 각자 맡을 가설을 고른다. 가설을 고르면 5절 템플릿으로 사전 등록 후 실행한다.

## 0. 큰 질문과 지금까지의 답

**큰 질문:** 텍스트와 이미지를 함께 쓰는 추천에서, 이미지는 **언제(어떤 조건에서) · 어디서(어떤 상품 · 고객에서) · 어떻게(어떤 표현과 결합 방식으로)** 도움이 되는가?

| 축 | 지금까지 알게 된 것 | 성격 |
|---|---|---|
| 이미지가 도움이 되는가 | 텍스트 위에 확실히 기여 (섞은 이미지 대비 상대 +0.09 ~ +0.19) | 탐색적 (모든 조건에서 구간 > 0) |
| 언제: 인코더 | 패션 도메인 적응은 효과 없음 / **사전학습**에 따라 약 2배 차이 | 확증 불지지 / 사후 탐색적 |
| 언제: 상품 ID | 드롭아웃 0.3 ID는 이미지 기여를 줄이지 않음 / **드롭아웃 없는 ID**는 약 25% 줄임 | 확증 불지지 / 사후 탐색적 |
| 어디서: 상품 유형 | 패턴 대 무지 차이 없음 (라벨 노이즈 민감도에서도 유지) | 확증 불지지 |
| 어디서: 상품 구매 기록 | **희소 · 신규 상품에서 약 2배 이상** | 사후 탐색적 |
| 어떻게: 결합 방식 · 학습 방식 | 아직 안 봄 (이어 붙이기 + 고정 임베딩만 사용) | 미검증 |
| 어디서: 고객 측 | 아직 안 봄 | 미검증 |

**핵심:** 사후 탐색적 결과 3개(사전학습, 구매 기록, ID 사용 방식)는 **결과를 보고 찾은 것**이라 아직 주장할 수 없다. 이것들을 **새 데이터 구간에서 사전 등록으로 재검증**하는 것이 가장 가치 있는 다음 실험이다 (4-1절).

## 1. 공통 설정 (모든 가설이 공유, 바꾸면 기존 결과와 비교 불가)

### 1-1. 데이터와 분할
| 항목 | 값 | 위치 |
|---|---|---|
| 원본 | H&M Personalized Fashion Recommendations, 구매 31,788,324건 (2018-09-20 ~ 2020-09-22) | 드라이브 `raw/` |
| 상품 | 53,232개 (분할 기간에 팔렸고 이미지가 있는 상품 전부). `idx` 순서가 모든 임베딩 행 순서 | `processed/items.parquet` |
| 고객 | 학습 기간 구매 5회 이상, 450,766명 | `processed/main/stats.json` |
| main 분할 | 학습 26주 (2020-03-11 ~ 09-08) · 검증 1주 (09-09 ~ 15) · 테스트 1주 (09-16 ~ 22) | `processed/main/` |
| alt 분할 | 테스트를 1주 앞당김 (테스트 09-09 ~ 15) | `processed/alt/` |
| 테스트 규모 (main) | 고객 46,054명, 구매 150,415건 | `stats.json` |
| 최종 학습 | 검증 주로 설정 선택 후 **학습 + 검증 기간**으로 다시 학습해 테스트 | `two_tower.run(mode="final")` |

**주의:** 새 테스트 주가 필요하면(재검증용) `data_prep.build_split(..., shift_weeks=k)`로 분할을 추가한다. 기존 `main`/`alt`는 바꾸지 않는다.

### 1-2. 평가 구간 (정답 구매를 나누는 기준)
| 구간 | 정의 | main 테스트 구매 수 |
|---|---|---|
| all | 테스트 주 전체 구매 | 150,415 |
| non_repurchase | 고객이 전체 기록에서 처음 사는 상품 | 143,355 |
| established | 학습 데이터에서 10회 이상 팔린 상품 | 136,816 |
| sparse | 학습 데이터에서 1~9회 팔린 상품 | 7,167 |
| new_item | 전체 기록 기준 테스트 주에 처음 팔린 상품 | 6,144 |
| 셀 (상품군 × 외관) | 상품군 6 (upper · lower · full · shoes · accessories · other) × 외관 3 (solid · pattern · texture) | `analysis_plan.yaml` 매핑 |

판매 횟수는 **학습에 실제로 쓰는 데이터**(구매 5회 이상 고객의 학습 + 검증 기간)로 센다 (2차 사전 등록 명확화).

### 1-3. 피처
| 피처 | 내용 | 파일 · 설정 |
|---|---|---|
| 텍스트 임베딩 | all-MiniLM-L6-v2. 입력 = `prod_name. product_type_name. colour_group_name. detail_desc` | `embeddings/text_minilm.npy` |
| 이미지 임베딩 7종 | `img_resnet50` (ImageNet) · `img_clipb32` (OpenAI CLIP B/32) · `img_laion_b32` (LAION-2B CLIP B/32) · `img_fashionclip2` (FashionCLIP 2.0, LAION 출발) · `img_siglip_b16` (SigLIP B/16 WebLI) · `img_marqo` (Marqo-FashionSigLIP, WebLI 출발) | `embeddings/img_*.npy` (+ `.json`에 구조 · PCA 정보) |
| 후처리 | 모든 임베딩 PCA 256차원 + L2 정규화 (텍스트 · 이미지 크기 맞춤) | `paper.yaml` embedding |
| 섞기 대응표 | 상품마다 다른 상품의 이미지를 배정. 전체 섞기(`global`) · 같은 `product_type_name` 안 섞기(`type`) × seed 42 · 43 · 44 | `embeddings/shuffle_*_seed*.npy` |
| 인기도 입력 | 직전 1주 · 4주 판매량 log1p z-점수 (라벨 주마다 그 주 이전으로 계산) | 조건 spec `pop: true` |
| 상품 ID 임베딩 | 학습되는 ID, 미등장 상품은 0, ID 드롭아웃 | 조건 spec `id: true`, 설정 i1~i4 (`prereg_v2.yaml`) |
| 상품 메타데이터 | `pgroup`, `appearance`, `graphical_appearance_name`, `product_type_name`, `colour_group_name`, `product_code`, `desc_mentions_pattern`(설명에 패턴 단어 있음) | `processed/items.parquet` |

### 1-4. 모델
| 모델 | 구조 | 코드 |
|---|---|---|
| **Two-Tower (기본, ID 없음)** | 상품 타워 = [텍스트 ⊕ 이미지] → MLP(512) → 128 / 고객 타워 = 최근 구매 50개의 상품 입력 평균 → MLP / 배치 내 부정 샘플 softmax, 온도 0.05 / 주 단위 학습 표본 (라벨 6주) | `two_tower.run` |
| + 인기도 | 상품 타워 입력에 인기도 2칸 추가 | spec `pop: true` |
| + 상품 ID | 상품 타워 입력에 ID 임베딩 추가 (고객 쪽 ID 없음) | spec `id: true` |
| 학습 없는 방식 | 고객 이력 임베딩 평균과 가까운 상품 (K0 텍스트, K2 텍스트 + Marqo) | `baselines.py` |
| 베이스라인 | B1 직전 1주 인기, B2 재구매 + 인기 | `baselines.py` |
| 학습 설정 (고정) | 학습률 0.0005, 8에폭, 배치 2048, 드롭아웃 0.1 (1차 튜닝 h2) | `paper.yaml` train.default |

### 1-5. 측정
| 이름 | 정의 | 언제 쓰나 |
|---|---|---|
| R | 고객별 평균 Recall@300 (구간별로는 그 구간 구매만으로 계산, 구매 없는 고객 제외) | 모든 비교의 기본 |
| 내용 기여도 (content) | R(텍스트 + 이미지) − R(텍스트 + **전체 섞은** 이미지). 입력 크기가 같아 "입력이 커진 효과" 통제 | **주 측정값** |
| 세밀 기여도 (fine) | R(텍스트 + 이미지) − R(텍스트 + **같은 품목 안 섞은** 이미지). 품목 정보를 넘어선 시각 정보 | 보조 |
| img 기여도 | R(텍스트 + 이미지) − R(텍스트만). 입력 크기가 달라 해석 주의 | 서술용만 |
| 상대값 | 위 차이 ÷ 대조군 R. 기본 성능이 다른 모델끼리 비교할 때 | ID 유무 비교 등 |
| 절대값 | 위 차이 그대로. **분모가 작은 구간(신규 · 희소)은 절대값으로** | 구간 비교 |
| 셀 비율 | 셀(상품군 × 외관)에 속한 구매 중 맞힌 비율 | 상품 유형 층화 |
| product_code 수준 | 색상만 다른 상품을 같은 상품으로 채점 | 색상 구분 효과 점검 |
| 통계 | 고객 단위 짝지은 부트스트랩 1,000회 (seed 42), 학습 seed 3개(42 · 43 · 44)별로 계산 후 평균 | 모든 구간 |

**재사용할 코드:** `analysis_v2.build_context` (채점 · 부트스트랩 공통), `contribution(cell, segment, measure, kind)`, `analysis_v2.POSTHOC` 형식의 대비 정의, `experiments.yaml v2_cells` (조건 묶음 정의).

## 2. 진행 규칙 (누락하면 결과를 논문에 못 씀)

1. **사전 등록 먼저:** 가설 · 비교 · 측정값 · 구간 · 판정 기준 · seed를 `paper/configs/prereg_<이름>.yaml`로 작성해 **실행 전에 커밋**한다 (5절 템플릿). 실행 후 바꾸지 않는다.
2. **확증 검정은 적게:** 한 사람당 확증 가설 1~2개. 2개 이상이면 본페로니 보정 (2개면 97.5% 구간). 나머지는 "탐색적"으로 표시.
3. **사후 결과를 확증처럼 쓰지 않기:** 같은 데이터에서 찾은 것을 같은 데이터로 "확인"하면 확증이 아니다. 재검증은 **새 테스트 주**(또는 다른 데이터)로 한다.
4. **조건 · 묶음 이름 충돌 방지:** 새 조건 ID와 묶음 이름에 담당자 접두어를 붙인다. 예) 김형우 `HW_`, 김광석 `KS_`, 김유환 `YH_`. 기존 A~G, C0~C12, P*, S*, L*, FC*, I*, J*는 건드리지 않는다.
5. **실행 환경:** Colab **L4**, **새 런타임**으로 시작 (옛 코드가 메모리에 남는 사고 방지). 셀 0의 `코드 커밋`을 기록한다.
6. **기존 결과 재사용:** 같은 조건을 다시 돌리지 않는다. 기존 실행은 `outputs/{묶음}/{분할}/{조건}_seed{s}/`에 있다 (3-4절).
7. **결과는 코드로만 채점:** `metrics.py` · `analysis_v2` 계열 함수로만 계산한다. 노트북에서 손으로 계산한 수치는 쓰지 않는다.
8. **기록:** 실행 후 `docs/실험기록.md`에 날짜 · 커밋 · 결과 · 해석을 남기고, 불지지도 그대로 보고한다.
9. **변경은 PR로:** 코드와 설정은 각자 브랜치 → upstream PR → 리뷰 1명 승인 후 머지.

## 3. 지금까지 검증한 가설

### 3-1. [1차 사전 등록] 이미지는 패턴 상품에 더 도움이 된다 — **불지지**
| 항목 | 내용 |
|---|---|
| 질문 | 어디서: 같은 상품군 안에서 패턴 · 프린트 상품과 무지 상품의 이미지 기여가 다른가 |
| 가설 | 세밀 기여도(같은 품목 안 섞기 대비)가 패턴 > 무지 |
| 피처 · 모델 | 텍스트(MiniLM) + 이미지(Marqo), ID 없는 Two-Tower |
| 조건 | C2 (텍스트 + Marqo) 대 C4 (같은 품목 안 섞기), 묶음 A, seed 3개 |
| 구간 · 측정 | non_repurchase, 셀 비율, 상품군별 (패턴 − 무지) → 구매 수 가중 평균 |
| 결과 | **+0.0018 [−0.0009, +0.0051]** (95%) |
| 민감도 | 오라벨 11개 제외 +0.0018 [−0.0009, +0.0050] · `All over pattern` 전체 제외 +0.0009 [−0.0023, +0.0049] — 모두 불지지 유지 |
| 남은 문제 | 라벨 판정이 1인(초기 판정 Claude, 팀 재검수 대기)이고 라벨을 보고 판정. 검사하지 않은 상품의 노이즈는 배제 불가 |
| 후속 아이디어 | 4-4절 (텍스트 정보량), 4-6절 (시각적 특이성) |

### 3-2. [2차 사전 등록 H1] 패션 도메인 적응이 이미지 기여를 키운다 — **불지지**
| 항목 | 내용 |
|---|---|
| 질문 | 언제: 같은 구조에서 패션 데이터로 추가 학습한 인코더가 이미지 기여를 키우는가 |
| 피처 · 모델 | 텍스트 + 이미지, ID 없는 Two-Tower |
| 조건 | 주 쌍: Marqo (C2 · C3) 대 범용 SigLIP B/16 (S2 · S3) / 재현 쌍: FashionCLIP 2.0 (FC2 · FC3) 대 LAION CLIP B/32 (L2 · L3) |
| 측정 | 상대 내용 기여도, 구간 all, 97.5% 구간 (본페로니) |
| 결과 | 주 쌍 **+0.0014 [−0.0218, +0.0237]** · 재현 쌍 +0.0026 [−0.0149, +0.0219] (95%, 같은 방향) |
| 해석 | 이 표본에서 패션 적응의 효과는 관찰되지 않음. 구간이 약 ±0.02라 이 범위의 효과는 배제 못 함 |

### 3-3. [2차 사전 등록 H2] 상품 ID가 이미지 기여를 가린다 — **불지지 (선택 설정 i4 기준)**
| 항목 | 내용 |
|---|---|
| 질문 | 언제: ID를 함께 쓰면 기존 상품에서 이미지 기여가 줄어드는가 |
| 조건 | Marqo, ID 없음 (C2 · C3, 묶음 A) 대 ID 있음 i4 = ID 64차원 · 드롭아웃 0.3 (I2 · I3, 묶음 F) |
| 측정 | 상대 내용 기여도, 구간 established, 97.5% 구간 |
| 결과 | **+0.0046 [−0.0200, +0.0308]** |
| 주의 | ID 모델은 과적합으로 ID 없는 모델보다 검증 성능이 약 20% 낮음 (강한 ID 모델 아님). 고객 쪽 ID 없음. 선택 설정의 드롭아웃이 H2를 보수적으로 만듦 |
| 후속 아이디어 | 4-3절 (드롭아웃 없는 ID · 강한 ID 모델로 재검증) |

## 4. 다음 가설 후보 (각자 하나씩 골라 사전 등록)

각 후보에 **우선순위 · 비용 · 필요한 코드**를 적었다. 비용은 Colab L4 기준 (Two-Tower 1회 약 20초 + 불러오기).

### 4-1. [재검증] 사전학습이 이미지 기여를 가른다 — 우선순위 높음
| 항목 | 내용 |
|---|---|
| 질문 | 언제: 같은 구조에서 사전학습 데이터가 다르면 이미지 기여가 달라지는가 |
| 근거 | 사후: 같은 CLIP B/32에서 LAION-2B 0.179 대 OpenAI 0.092, 차이 +0.087 [+0.069, +0.106] |
| 가설 (방향) | LAION-2B CLIP B/32의 상대 내용 기여도 > OpenAI CLIP B/32 |
| 피처 | 텍스트 MiniLM + `img_laion_b32` / `img_clipb32` (이미 있음) |
| 모델 · 조건 | ID 없는 Two-Tower. 조건 L2 · L3 대 C10 · C11과 같은 구성 (새 조건 ID로) |
| 새 데이터 | **새 테스트 주** 2~3개 (예: shift 2 · 3 · 4주). 기존 main/alt는 발견에 쓴 데이터라 재검증에 쓰지 않음 |
| 측정 · 판정 | 상대 내용 기여도, 구간 all, 새 테스트 주별 seed 3개, 95% 구간 하한 > 0 (주 수만큼 보정할지 사전 등록에 명시) |
| 필요한 코드 | `build_split(shift_weeks=k)`로 분할 추가, 분할 이름 추가 (`config.SPLITS`), 조건 · 묶음 추가. 임베딩 · 섞기 대응표는 재사용 (상품 집합이 같은지 확인 — 다르면 상품 선택 범위 재검토 필요) |
| 비용 | 주 3개 × 조건 4개 × seed 3 = 36회, 약 30~40분 |
| 해석 주의 | OpenAI와 LAION은 데이터 양과 구성이 함께 달라 원인을 하나로 특정 불가. 지지돼도 "사전학습 데이터가 다른 같은 구조" 이상으로 쓰지 않음 |
| 추가 확장 (선택) | 같은 구조 다른 사전학습 쌍 추가 (예: SigLIP 대 같은 구조 다른 데이터) |

### 4-2. [재검증] 구매 기록이 적은 상품에서 이미지가 더 도움이 된다 — 우선순위 높음
| 항목 | 내용 |
|---|---|
| 질문 | 어디서: 상품의 학습 데이터 판매 횟수가 적을수록 이미지 기여가 커지는가 |
| 근거 | 사후: Marqo 희소 − 기존 절대 +0.021 [+0.016, +0.027], 신규 − 기존 +0.016 [+0.011, +0.022]. 모든 인코더에서 같은 방향 |
| 가설 (방향) | 절대 내용 기여도: 희소(1~9회) > 기존(10회 이상), 신규 > 기존 |
| 피처 · 모델 | 텍스트 + Marqo (또는 범용 SigLIP), ID 없는 Two-Tower |
| 새 데이터 | 4-1과 같은 새 테스트 주 (같은 실행을 공유하면 비용 절약) |
| 측정 · 판정 | **절대값**으로 (분모 착시 방지). 구간 간 차이의 짝지은 부트스트랩 구간. 가능하면 판매 횟수를 연속 변수로 (0 · 1~2 · 3~9 · 10~49 · 50+ 구간별 기여도 추세) |
| 필요한 코드 | 구간 정의 확장 (`analysis_v2.segment_masks`에 판매 횟수 구간 추가), 구간 간 대비 (`POSTHOC` 형식) |
| 비용 | 4-1과 실행 공유 시 추가 학습 없음 |
| 해석 주의 | 희소 · 신규 상품은 구매 수가 적어 구간이 넓음. 판매 횟수는 상품 인기도와 얽혀 있어 "기록이 적어서"인지 "덜 인기 있는 상품이라서"인지 분리하려면 인기도 입력 모델(묶음 D)과 비교 필요 |

### 4-3. [재검증 · 확장] ID를 그대로 쓰면 이미지 기여가 줄어든다 — 우선순위 중간
| 항목 | 내용 |
|---|---|
| 질문 | 언제: ID 의존이 커질수록 이미지 기여가 줄어드는가 |
| 근거 | 사후: 드롭아웃 0(i2)에서 기존 상품 Marqo 상대 기여도 0.167 → 0.126, 차이 +0.041 [+0.020, +0.064]. 확증(i4)에서는 차이 없음 |
| 가설 (방향) | ID 드롭아웃이 작을수록(ID 의존 ↑) 기존 상품의 이미지 기여 ↓ (용량 반응: 드롭아웃 0 · 0.1 · 0.3 · 0.5) |
| 피처 · 모델 | 텍스트 + Marqo, ID 있는 Two-Tower. **강한 ID 모델** 버전 추가 권장: ID 임베딩에 가중치 감쇠 · 조기 종료를 넣어 ID 없는 모델 이상의 검증 성능을 먼저 확보 |
| 새 데이터 | 새 테스트 주 (4-1과 공유) |
| 측정 · 판정 | 상대 · 절대 내용 기여도, 구간 established. 드롭아웃에 따른 단조 추세 |
| 필요한 코드 | `two_tower.train`에 ID 가중치 감쇠 · 조기 종료 옵션, ID 설정 후보 추가 (`prereg_<이름>.yaml`에) |
| 비용 | 드롭아웃 4개 × 조건 3개 × seed 3 = 36회 |
| 해석 주의 | 고객 쪽 ID 없음 (Ye 외와 다름). 신규 상품의 ID 0 입력 불일치 때문에 신규 상품 상대값은 쓰지 않음 |

### 4-4. [신규] 텍스트가 시각 정보를 담지 못할 때 이미지가 더 도움이 된다 — 우선순위 높음
| 항목 | 내용 |
|---|---|
| 질문 | 어디서: 상품 설명이 외관(패턴 · 색 · 디자인)을 덜 설명할수록 이미지 기여가 커지는가 |
| 근거 | 1차 가설(패턴 대 무지)이 불지지인 이유 후보: H&M 설명에 패턴 정보가 이미 있어서. `desc_mentions_pattern` 피처가 이미 있음 (아직 분석 안 함) |
| 가설 (방향) | 패턴 상품 중 설명에 패턴 언급이 **없는** 상품의 기여 > 언급이 **있는** 상품 |
| 피처 | `desc_mentions_pattern` (items.parquet), 확장: 설명 길이, 설명 결측 여부, 색상명 언급 여부 |
| 모델 · 조건 | 기존 실행 그대로 (C2 · C3 · C4) → **재학습 없이** 채점 구간만 새로 정의. 단 기존 main은 이미 본 데이터이므로, 확증으로 쓰려면 새 테스트 주에서 |
| 측정 · 판정 | 셀 비율 또는 절대 내용 기여도, 상품군 층화 (패턴 대 무지 때와 같은 방식) |
| 필요한 코드 | `segment_masks`에 텍스트 정보량 구간 추가, 층화 대비 함수 재사용 (`analysis._pattern_minus_solid` 형식) |
| 비용 | 기존 결과 재채점만 하면 몇 분. 새 테스트 주에서 하면 4-1 실행 공유 |
| 해석 주의 | 패턴 단어 목록은 사전 등록된 정규식 그대로 쓰고 바꾸지 않음. 라벨 노이즈 (pattern 표본 일치율 77.5%) |

### 4-5. [신규] 텍스트 인코더가 강하면 이미지 기여가 줄어든다 — 우선순위 중간
| 항목 | 내용 |
|---|---|
| 질문 | 언제: "텍스트 지배"가 텍스트 표현의 품질에 달렸는가 |
| 근거 | 우리는 작은 텍스트 인코더(MiniLM) 하나만 씀. 텍스트가 강해지면 이미지가 더해줄 몫이 줄 수 있음 |
| 가설 (방향) | 텍스트 인코더가 강할수록(MiniLM → e5 · bge 등 큰 모델) 이미지 상대 기여도 ↓ |
| 피처 | 새 텍스트 임베딩 1~2종 추가 (`text_*.npy`), 이미지는 Marqo 고정 |
| 모델 · 조건 | ID 없는 Two-Tower. 각 텍스트 인코더마다 텍스트만 · 텍스트 + 이미지 · 텍스트 + 섞은 이미지 |
| 측정 · 판정 | 상대 내용 기여도, 구간 all · established |
| 필요한 코드 | `item_features`에서 텍스트 임베딩 파일 이름을 조건 spec으로 고를 수 있게 (현재 `text_minilm` 고정), 임베딩 추출 (01 노트북 방식) |
| 비용 | 텍스트 임베딩 추출 몇 분 × 개수, 학습 텍스트 인코더 2개 × 조건 3개 × seed 3 = 18회 |
| 해석 주의 | 텍스트 인코더마다 텍스트만 성능 자체가 다르므로 상대값 · 절대값을 함께 보고 |

### 4-6. [신규] 시각적으로 특이한 상품에서 이미지가 더 도움이 된다 — 우선순위 중간
| 항목 | 내용 |
|---|---|
| 질문 | 어디서: 같은 품목 안에서 이미지가 남들과 다른 상품일수록 이미지 기여가 커지는가 |
| 근거 | 선행 연구(VisGate, 2026, 【원문 확인 필요】)가 "시각적 특이성"과 시각 정보 유용성의 관련을 보고. 우리 1차 가설(패턴)은 라벨 기반이었고, 이건 **임베딩 기반** 측정 |
| 가설 (방향) | 같은 `product_type_name` 안에서 이미지 임베딩이 품목 중심에서 먼 상품(특이성 상위)의 기여 > 하위 |
| 피처 | 특이성 = 이미지 임베딩과 같은 품목 평균 임베딩의 코사인 거리 (Marqo 기준. 다른 인코더로 계산하면 순환 논리 주의) |
| 모델 · 조건 | 기존 실행 (재학습 없음) 또는 새 테스트 주 |
| 측정 · 판정 | 특이성 분위수(예: 하위 · 중간 · 상위 1/3)별 절대 내용 기여도, 품목 층화 |
| 필요한 코드 | 상품별 특이성 계산 스크립트, 구간 추가 |
| 해석 주의 | 특이성을 기여도를 잴 때 쓰는 인코더로 계산하면 결과가 그 인코더에 유리하게 나올 수 있음 → 특이성은 **다른 인코더**로 계산하거나 두 경우를 모두 보고 |

### 4-7. [신규] 이력이 짧은 고객에게 이미지가 더 도움이 된다 — 우선순위 중간
| 항목 | 내용 |
|---|---|
| 질문 | 어디서(고객 측): 고객의 구매 이력 길이 · 취향 다양성에 따라 이미지 기여가 다른가 |
| 근거 | 지금까지 상품 측만 봄. 고객 쪽 콜드스타트도 콘텐츠 의존이 클 수 있음 |
| 가설 (방향) | 학습 기간 구매 수가 적은 고객(예: 5~9회)의 기여 > 많은 고객(30회 이상) |
| 피처 | 고객별 학습 데이터 구매 수, 이력의 품목 다양성(엔트로피) |
| 모델 · 조건 | 기존 실행 그대로, 고객 그룹으로 나눠 채점 |
| 측정 · 판정 | 고객 그룹별 R과 내용 기여도 (상대 · 절대). 부트스트랩은 그룹 안 고객 재추출 |
| 필요한 코드 | 고객 그룹 마스크 (구매 구간이 아니라 고객 단위로 나누는 함수) |
| 해석 주의 | 고객 필터가 "5회 이상"이라 진짜 신규 고객은 없음. 이력 길이는 활동성 · 구매 수와 얽혀 있음 |

### 4-8. [신규] 결합 방식이 이미지 활용을 바꾼다 (어떻게) — 우선순위 낮음 (비용 큼)
| 항목 | 내용 |
|---|---|
| 질문 | 어떻게: 이어 붙이기 대신 다른 결합 방식을 쓰면 이미지 기여가 달라지는가 |
| 근거 | 우리는 이어 붙이기 + MLP만 사용. Ye 외는 "결합 방식에 따라 이미지 민감도가 다르다"고 보고 (GRCN · LGMRec 등) |
| 후보 | ① 모달리티별 별도 타워 후 합산(late fusion) ② 상품별 게이트(이미지 가중치 학습) ③ 모달리티 드롭아웃(학습 중 텍스트를 가끔 0으로) |
| 가설 (예) | 모달리티 드롭아웃을 쓰면 이미지 기여 ↑ (텍스트 지배 완화) |
| 필요한 코드 | `two_tower.build_model` · `train` 수정 (상품 타워 구조 옵션) |
| 비용 | 결합 방식 2~3개 × 조건 3개 × seed 3 = 18~27회 + 구현 시간 |
| 해석 주의 | 모델 구조가 바뀌면 기본 성능이 달라지므로 상대 · 절대 모두 보고. 하이퍼파라미터 튜닝 규칙 사전 등록 |

### 4-9. [신규] 이미지 인코더를 함께 학습하면 이미지 기여가 커진다 (어떻게) — 우선순위 낮음 (비용 매우 큼)
| 항목 | 내용 |
|---|---|
| 질문 | 어떻게: 고정 임베딩 대신 인코더 일부를 추천 데이터로 학습하면 이미지 기여가 커지는가 |
| 근거 | MoRec (2023, 【원문 확인 필요】)은 끝까지 학습해야 이미지 기반 모델이 경쟁력 있다고 보고. 우리는 고정 임베딩만 사용 |
| 가설 (예) | 마지막 몇 층 또는 어댑터만 학습해도 기여 ↑ |
| 비용 | 이미지 5만 장을 매 에폭 인코딩해야 해서 L4로도 1회 수십 분~수 시간. 3주 일정에는 부담 |
| 권장 | 이번 논문 범위 밖. 한계 · 향후 연구로 적기 |

## 5. 사전 등록 템플릿

`paper/configs/prereg_<이름>.yaml`로 저장하고 **실행 전에 커밋**한다.

```yaml
status: final
registered: 2026-10-XX            # 커밋 날짜와 맞출 것
owner: 김형우                       # 담당
hypothesis_id: HW_text_info        # 4절 후보 번호 또는 새 이름
question: "텍스트가 시각 정보를 담지 못할 때 이미지가 더 도움이 되는가"
direction: "설명에 패턴 언급이 없는 패턴 상품의 절대 내용 기여도 > 언급이 있는 패턴 상품"
data:
  split: [main_s2, main_s3]        # 새 테스트 주 (발견에 쓴 main/alt는 확증에 쓰지 않음)
  segments: {...}                  # 구간 정의 (판매 횟수 기준 데이터 명시)
features: {text: text_minilm, image: marqo, extra: desc_mentions_pattern}
model: {type: two_tower_noid, train_params: paper.yaml train.default}
conditions:                        # 새 조건 ID는 담당자 접두어
  HW_T: {text: true, image: null, shuffle: null}
  HW_R: {text: true, image: marqo, shuffle: null}
  HW_G: {text: true, image: marqo, shuffle: global}
seeds: [42, 43, 44]
measure: {primary: absolute_content, also_report: relative_content, metric: "고객별 평균 Recall@300"}
confirmatory:
  - name: H_HW1
```
