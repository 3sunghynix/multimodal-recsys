> 3성하이닉스 팀 공유용 · 2026-10-12 작성, **2026-10-13 개정 (4 · 6절: 선행 연구 조사 반영, [선행연구조사.md](선행연구조사.md))** · 작성 김유환
> 근거: [실험기록.md](실험기록.md) (모든 수치의 출처) · [주제재검토.md](주제재검토.md) · 사전 등록 [`analysis_plan.yaml`](../paper/configs/analysis_plan.yaml), [`prereg_v2.yaml`](../paper/configs/prereg_v2.yaml)
> **사용법:** 1절(공통 설정)과 2절(진행 규칙)을 먼저 읽고, 3절에서 지금까지의 결과를, 4절에서 각자 맡을 가설을 고른다. 가설을 고르면 5절 템플릿으로 사전 등록 후 실행한다.

## 0. 큰 질문과 지금까지의 답

**큰 질문:** 텍스트와 이미지를 함께 쓰는 추천에서, 이미지는 **언제(어떤 조건에서) · 어디서(어떤 상품 · 고객에서) · 어떻게(어떤 표현과 결합 방식으로)** 도움이 되는가?

| 축 | 지금까지 알게 된 것 | 성격 |
|---|---|---|
| 이미지가 도움이 되는가 | 텍스트 위에 확실히 기여 (섞은 이미지 대비 상대 +0.09 ~ +0.19) | 탐색적 (모든 조건에서 구간 > 0) |
| 언제: 인코더 | 패션 도메인 적응은 효과 없음 / **사전학습**에 따라 약 2배 차이 | 확증 불지지 / 사후 탐색적 |
| 언제: 상품 ID | 드롭아웃 0.3 ID는 이미지 기여를 줄이지 않음 / **드롭아웃 없는 ID**는 약 25% 줄임 | 확증 불지지 / 사후 탐색적 |
| 어디서: 상품 유형 | 패턴 대 무지 차이 없음 (라벨 노이즈 민감도에서도 유지) | 확증 불지지 |
| 어디서: 상품 구매 기록 | **희소 · 신규 상품에서 약 2배 이상** | 사후 탐색적 |
| 어떻게: 결합 · 학습 균형 | 아직 안 봄 (이어 붙이기 + 고정 임베딩만 사용). 선행 연구가 꼽는 핵심 처방(모달리티 드롭아웃 · 결합 구조 · 정규화 · logQ) | **미검증 → 4-3 ~ 4-6 (최우선)** |
| 어디서: 고객 측 | 아직 안 봄 | 미검증 |

**핵심 (10-13 개정):** 논문 축을 **RQ1 어떤 인코더 · RQ2 어떻게 결합 · 학습 · RQ3 어디에**로 재구성한다. 가장 큰 빈칸은 RQ2(어떻게)이고, 아직 결과를 보지 않은 새 질문이라 **main에서 사전 등록 후 바로 확증**할 수 있다 (4-3 · 4-4 · 4-6). 사후 결과 3개(사전학습, 구매 기록, ID)는 새 테스트 주에서 재검증한다 (4-1 · 4-8 · 4-9).

### 1-4. 모델
| 모델 | 구조 | 코드 |
|---|---|---|
| **Two-Tower (기본, ID 없음)** | 상품 타워 = [텍스트 ⊕ 이미지] → MLP(512) → 128 / 고객 타워 = 최근 구매 50개의 상품 입력 평균 → MLP / 배치 내 부정 샘플 softmax, 온도 0.05 / 주 단위 학습 표본 (라벨 6주) | `two_tower.run` |
| + 인기도 | 상품 타워 입력에 인기도 2칸 추가 | spec `pop: true` |
| + 상품 ID | 상품 타워 입력에 ID 임베딩 추가 (고객 쪽 ID 없음) | spec `id: true` |
| 학습 없는 방식 | 고객 이력 임베딩 평균과 가까운 상품 (K0 텍스트, K2 텍스트 + Marqo) | `baselines.py` |
| 베이스라인 | B1 직전 1주 인기, B2 재구매 + 인기 | `baselines.py` |
| 학습 설정 (고정) | 학습률 0.0005, 8에폭, 배치 2048, 드롭아웃 0.1 (1차 튜닝 h2) | `paper.yaml` train.default |

### 1-5. 측정
| 이름 | 정의 | 언제 쓰나 |
|---|---|---|
| R | 고객별 평균 Recall@300 (구간별로는 그 구간 구매만으로 계산, 구매 없는 고객 제외) | 모든 비교의 기본 |
| 내용 기여도 (content) | R(텍스트 + 이미지) − R(텍스트 + **전체 섞은** 이미지). 입력 크기가 같아 "입력이 커진 효과" 통제 | **주 측정값** |
| 세밀 기여도 (fine) | R(텍스트 + 이미지) − R(텍스트 + **같은 품목 안 섞은** 이미지). 품목 정보를 넘어선 시각 정보 | 보조 |
| img 기여도 | R(텍스트 + 이미지) − R(텍스트만). 입력 크기가 달라 해석 주의 | 서술용만 |
| 상대값 | 위 차이 ÷ 대조군 R. 기본 성능이 다른 모델끼리 비교할 때 | ID 유무 비교 등 |
| 절대값 | 위 차이 그대로. **분모가 작은 구간(신규 · 희소)은 절대값으로** | 구간 비교 |
| 셀 비율 | 셀(상품군 × 외관)에 속한 구매 중 맞힌 비율 | 상품 유형 층화 |
| product_code 수준 | 색상만 다른 상품을 같은 상품으로 채점 | 색상 구분 효과 점검 |
| 통계 | 고객 단위 짝지은 부트스트랩 1,000회 (seed 42), 학습 seed 3개(42 · 43 · 44)별로 계산 후 평균 | 모든 구간 |

**재사용할 코드:** `analysis_v2.build_context` (채점 · 부트스트랩 공통), `contribution(cell, segment, measure, kind)`, `analysis_v2.POSTHOC` 형식의 대비 정의, `experiments.yaml v2_cells` (조건 묶음 정의).

## 2. 진행 규칙 (누락하면 결과를 논문에 못 씀)

1. **사전 등록 먼저:** 가설 · 비교 · 측정값 · 구간 · 판정 기준 · seed를 `paper/configs/prereg_<이름>.yaml`로 작성해 **실행 전에 커밋**한다 (5절 템플릿). 실행 후 바꾸지 않는다.
2. **확증 검정은 적게:** 한 사람당 확증 가설 1~2개. 2개 이상이면 본페로니 보정 (2개면 97.5% 구간). 나머지는 "탐색적"으로 표시.
3. **사후 결과를 확증처럼 쓰지 않기:** 같은 데이터에서 찾은 것을 같은 데이터로 "확인"하면 확증이 아니다. 재검증은 **새 테스트 주**(또는 다른 데이터)로 한다.
4. **조건 · 묶음 이름 충돌 방지:** 새 조건 ID와 묶음 이름에 담당자 접두어를 붙인다. 예) 김형우 `HW_`, 김광석 `KS_`, 김유환 `YH_`. 기존 A~G, C0~C12, P*, S*, L*, FC*, I*, J*는 건드리지 않는다.
5. **실행 환경:** Colab **L4**, **새 런타임**으로 시작 (옛 코드가 메모리에 남는 사고 방지). 셀 0의 `코드 커밋`을 기록한다.
6. **기존 결과 재사용:** 같은 조건을 다시 돌리지 않는다. 기존 실행은 `outputs/{묶음}/{분할}/{조건}_seed{s}/`에 있다 (3-4절).
7. **결과는 코드로만 채점:** `metrics.py` · `analysis_v2` 계열 함수로만 계산한다. 노트북에서 손으로 계산한 수치는 쓰지 않는다.
8. **기록:** 실행 후 `docs/실험기록.md`에 날짜 · 커밋 · 결과 · 해석을 남기고, 불지지도 그대로 보고한다.
9. **변경은 PR로:** 코드와 설정은 각자 브랜치 → upstream PR → 리뷰 1명 승인 후 머지.

## 3. 지금까지 검증한 가설

### 3-1. [1차 사전 등록] 이미지는 패턴 상품에 더 도움이 된다 — **불지지**
| 항목 | 내용 |
|---|---|
| 질문 | 어디서: 같은 상품군 안에서 패턴 · 프린트 상품과 무지 상품의 이미지 기여가 다른가 |
| 가설 | 세밀 기여도(같은 품목 안 섞기 대비)가 패턴 > 무지 |
| 피처 · 모델 | 텍스트(MiniLM) + 이미지(Marqo), ID 없는 Two-Tower |
| 조건 | C2 (텍스트 + Marqo) 대 C4 (같은 품목 안 섞기), 묶음 A, seed 3개 |
| 구간 · 측정 | non_repurchase, 셀 비율, 상품군별 (패턴 − 무지) → 구매 수 가중 평균 |
| 결과 | **+0.0018 [−0.0009, +0.0051]** (95%) |
| 민감도 | 오라벨 11개 제외 +0.0018 [−0.0009, +0.0050] · `All over pattern` 전체 제외 +0.0009 [−0.0023, +0.0049] — 모두 불지지 유지 |
| 남은 문제 | 라벨 판정이 1인(초기 판정 Claude, 팀 재검수 대기)이고 라벨을 보고 판정. 검사하지 않은 상품의 노이즈는 배제 불가 |
| 후속 아이디어 | 텍스트 정보량은 보류 · 시각 특이성은 제외 (4-0절 개정). 대신 "어떻게" 축(4-3 ~ 4-6)으로 이동 |

### 3-2. [2차 사전 등록 H1] 패션 도메인 적응이 이미지 기여를 키운다 — **불지지**
| 항목 | 내용 |
|---|---|
| 질문 | 언제: 같은 구조에서 패션 데이터로 추가 학습한 인코더가 이미지 기여를 키우는가 |
| 피처 · 모델 | 텍스트 + 이미지, ID 없는 Two-Tower |
| 조건 | 주 쌍: Marqo (C2 · C3) 대 범용 SigLIP B/16 (S2 · S3) / 재현 쌍: FashionCLIP 2.0 (FC2 · FC3) 대 LAION CLIP B/32 (L2 · L3) |
| 측정 | 상대 내용 기여도, 구간 all, 97.5% 구간 (본페로니) |
| 결과 | 주 쌍 **+0.0014 [−0.0218, +0.0237]** · 재현 쌍 +0.0026 [−0.0149, +0.0219] (95%, 같은 방향) |
| 해석 | 이 표본에서 패션 적응의 효과는 관찰되지 않음. 구간이 약 ±0.02라 이 범위의 효과는 배제 못 함 |

### 3-3. [2차 사전 등록 H2] 상품 ID가 이미지 기여를 가린다 — **불지지 (선택 설정 i4 기준)**
| 항목 | 내용 |
|---|---|
| 질문 | 언제: ID를 함께 쓰면 기존 상품에서 이미지 기여가 줄어드는가 |
| 조건 | Marqo, ID 없음 (C2 · C3, 묶음 A) 대 ID 있음 i4 = ID 64차원 · 드롭아웃 0.3 (I2 · I3, 묶음 F) |
| 측정 | 상대 내용 기여도, 구간 established, 97.5% 구간 |
| 결과 | **+0.0046 [−0.0200, +0.0308]** |
| 주의 | ID 모델은 과적합으로 ID 없는 모델보다 검증 성능이 약 20% 낮음 (강한 ID 모델 아님). 고객 쪽 ID 없음. 선택 설정의 드롭아웃이 H2를 보수적으로 만듦 |
| 후속 아이디어 | 4-9절 (드롭아웃 없는 ID · 강한 ID 모델로 재검증) |

### 3-4. 재사용 가능한 기존 실행 (다시 돌리지 말 것)
| 묶음 | 분할 | 조건 (seed) | 내용 |
|---|---|---|---|
| A | main | C0 · C2 · C3 · C4 (42 · 43 · 44), C1 (42) | 텍스트만, Marqo (진짜 · 전체 섞기 · 품목 안 섞기 · 이미지만) |
| B | main | C0 · C5~C8 (42 · 43 · 44) | ResNet-50 |

### 4-3. [RQ2 · 신규] 텍스트 모달리티 드롭아웃이 이미지 활용과 성능을 함께 올린다 — **최우선**
> **결과 (2026-10-14): H3 지지** — p = 0.1에서 +0.0019 [+0.0007, +0.0031] (97.5%). 단 이미지 기여도는 p가 클수록 **감소**해 메커니즘은 반대. 대조군인 **이미지 드롭아웃**이 더 좋음(최대 +0.0042, 탐색적) → 새 가설 후보. 상세: `docs/실험기록.md` 2026-10-14
> 사전 등록 [`prereg_yh_fusion.yaml`](../paper/configs/prereg_yh_fusion.yaml) (4-4와 함께, 확증 H3 · H4, 본페로니 97.5%), 노트북 `08_yh_fusion`, 분석 `analysis_yh.py`, 결과 드라이브 `results_yh/`. 사전 등록본은 p 3개를 모두 실행하고(18회) 이미지 드롭아웃 대조(18회)도 함께 돌린다

| 항목 | 내용 |
|---|---|
| 질문 | 학습 중 텍스트를 가끔 가리면, 모델이 이미지를 더 쓰고 전체 성능도 오르는가 |
| 근거 | Ye 외: "텍스트가 배우기 쉬워 시각 신호를 덮는다". CKD(ACM MM 2024): 약한 모달리티가 덜 최적화됨. SMD(CIKM 2026): 모달리티 드롭아웃이 전체 정확도 손실 거의 없이 강건성 1.0~3.2배. LRMM(2018) · DropoutNet(2017): 입력 드롭아웃으로 콘텐츠 활용 강제. 우리 ID 드롭아웃(i1~i4)과 같은 원리 |
| 가설 (방향) | ① 텍스트 드롭아웃 p > 0에서 텍스트 + Marqo 모델의 **전체 R**이 p = 0보다 높다 ② 상대 내용 기여도가 p에 따라 증가한다 |
| 방법 | 학습 중 상품 타워 입력의 **텍스트 블록(앞 256칸)을 상품별 확률 p로 0**으로 바꾼다. 고객 타워 입력(이력 평균)과 추천 시에는 그대로. p ∈ {0, 0.1, 0.3, 0.5} |
| 조건 | 각 p마다 텍스트 + Marqo 진짜 · 전체 섞기 (p = 0은 기존 C2 · C3 재사용). 선택: 텍스트만 조건에는 드롭아웃 의미 없음 |
| 데이터 | main (사전 등록 후) |
| 측정 · 판정 | 확증 ①: R(p 선택값) − R(p = 0)의 95% 하한 > 0. **p 선택은 검증 주에서** (사전 등록: 검증 주 R 1등 p를 테스트에 적용). 탐색: 기여도의 p 추세, 텍스트를 뺐을 때 성능 유지율 |
| 코드 | spec에 `text_dropout: p`, `train()` 배치 루프에서 `Xt[ib]`의 앞 256칸에 마스크 곱 (ID 드롭아웃 코드와 같은 형태) |
| 비용 | 튜닝 3회 + 테스트 p 3개 × 조건 2 × seed 3 = 18회, 약 15분 |
| 해석 주의 | 드롭아웃은 규제 효과도 있음 → 이미지 블록 드롭아웃(같은 p) 대조를 탐색적으로 함께 돌리면 "텍스트를 가려서"인지 "그냥 규제라서"인지 구분 가능 (+9회) |

### 4-4. [RQ2 · 신규] 결합 구조가 이미지 활용을 바꾼다 — **최우선**
> **결과 (2026-10-14): H4 불지지** — gate − 이어 붙이기 +0.0005 [−0.0007, +0.0018] (97.5%). 게이트 α가 상품마다 거의 같음(평균 0.48, 표준편차 0.02). 상세: `docs/실험기록.md` 2026-10-14

| 항목 | 내용 |
|---|---|
| 질문 | 이어 붙이기 대신 모달리티별로 따로 처리한 뒤 합치면 이미지가 덜 묻히는가 |
| 근거 | 서베이(Zhou 외): 이른 · 중간 · 늦은 결합 분류. Ye 외: 모델(결합 방식)마다 이미지 민감도가 크게 다름, 향후 과제로 결합 설계. ItemSage(KDD 2022): 이미지 · 텍스트 트랜스포머 결합이 단일 모달 대비 크게 우수 (실서비스). Kieu 외 2025: 단순 결합이 시각 기여를 약하게 만든다. VisGate(CARS@RecSys 2026): 상품 단위 게이트, 희소할수록 시각 의존 ↑ |
| 가설 (방향) | 게이트 결합의 전체 R과 상대 내용 기여도 > 이어 붙이기 |
| 구조 | ① 이어 붙이기 (현재) ② 늦은 결합: 텍스트 MLP · 이미지 MLP를 따로 통과 → 합산 ③ 게이트: ②의 두 출력을 상품별 학습 가중치 α(입력 전체로 계산한 시그모이드)로 가중 합. 고객 타워는 같은 구조를 따름 |
| 조건 | 구조 3개 × (텍스트 + Marqo 진짜 · 전체 섞기) × seed 3 (① 재사용) |
| 데이터 | main (사전 등록 후) |
| 측정 · 판정 | 확증: 게이트 − 이어 붙이기의 전체 R 차이 95% 하한 > 0. 탐색: 상대 · 절대 기여도, 게이트 α 분포(구매 기록 · 상품 유형 · 시각 특이성별 이미지 가중치 → RQ3와 연결) |
| 코드 | `two_tower.build_model`에 `fusion: concat | late | gate` 옵션, 입력을 텍스트 · 이미지 블록으로 나눠 받기 |
| 비용 | 구현 반나절 + 12회 |
| 해석 주의 | 구조마다 파라미터 수가 다름 → 은닉 크기를 맞추거나 파라미터 수를 보고. 학습 설정은 h2 고정을 사전 등록 (구조별 재튜닝 안 함, 또는 같은 규칙으로 모두 튜닝) |

### 4-5. [RQ2 · 신규] 텍스트와 이미지 입력의 크기 균형이 이미지 기여를 좌우한다 — 우선순위 중간
| 항목 | 내용 |
|---|---|
| 질문 | 우리가 이미지 기여를 크게 본 이유 중 하나가 "텍스트 · 이미지를 같은 크기로 정규화한 것"인가 |
| 근거 | Ye 외 5.2 · 6.2절: 미리 뽑은 텍스트는 정규화되고 이미지는 아님, 이미지 임베딩이 더 흩어져 있음, "인코더별 정규화 · 재조정이 필요할 수 있다". 우리는 둘 다 PCA 256 + L2 |
| 가설 (방향) | 이미지 블록에 배율 s를 곱할 때 상대 내용 기여도가 s = 0.5 < s = 1 |
| 조건 | s ∈ {0.5, 1, 2} × (텍스트 + Marqo 진짜 · 전체 섞기) × seed 3 (s = 1 재사용) |
| 데이터 | main |
| 측정 · 판정 | 상대 내용 기여도 차이 (s = 1 − s = 0.5), 95% 하한 > 0. 선택 확장: 원 차원 · L2 없음 (원 임베딩 재추출 필요, 탐색적) |
| 코드 | `item_features`에서 spec `img_scale` 적용 (한 줄) |
| 비용 | 12회 |
| 해석 주의 | 첫 MLP 층이 배율을 학습으로 보정할 수 있어 차이가 작을 수 있음. 작게 나오면 "정규화가 원인은 아니다"라는 정보 |

### 4-6. [RQ2 · 신규] logQ 보정으로 베이스라인 격차를 줄여도 이미지 기여는 남는다 — 우선순위 높음
| 항목 | 내용 |
|---|---|
| 질문 | 모델이 인기도를 제대로 배우게 하면 베이스라인에 근접하는가, 그때도 이미지가 기여하는가 |
| 근거 | Google RecSys 2019: 배치 내 부정 샘플은 인기 상품을 과하게 벌줌 → logQ 보정. 후속 RecSys 2025(2507.09331)가 보정식 수정 제안. 우리 실험기록의 추정 원인과 정확히 같음. **리뷰어가 가장 먼저 지적할 약점(모델 0.106 대 B2 0.257)** 을 직접 다룸 |
| 가설 (방향) | ① logQ 보정이 텍스트 + Marqo 모델의 전체 R을 높인다 ② 보정 모델에서도 절대 내용 기여도 > 0 |
| 방법 | 학습 logits에서 상품별 log(학습 데이터 출현 확률)를 뺌 (추천 시에는 빼지 않음). 출현 확률은 학습 표본의 상품 빈도 |
| 조건 | 텍스트만 · 텍스트 + Marqo 진짜 · 전체 섞기 × seed 3 = 9회 (+ 인기도 입력 P 조건과 결합은 탐색적) |
| 데이터 | main |
| 측정 · 판정 | ① R(logQ) − R(기존) 95% 하한 > 0 ② 내용 기여도 95% 하한 > 0. 탐색: B2와의 격차, 재구매 · 기존 · 신규 구간별 |
| 코드 | `train()`에서 `logits -= logq[ib][None, :]` 한 줄 + 빈도 계산 |
| 비용 | 9회 |
| 해석 주의 | 보정으로 인기 상품 쪽 성능이 오르면 이미지 상대 기여도는 줄 수 있음 → 상대 · 절대 모두 보고. 결합 후보 분석(B2 ∪ 모델)과 함께 보면 격차 논의가 완성됨 |

### 4-7. [RQ2 · 신규] 같은 공간의 텍스트 인코더를 쓰면 이미지 기여가 달라진다 — 우선순위 낮음
| 항목 | 내용 |
|---|---|
| 질문 | 텍스트를 이미지와 같은 모델(SigLIP 텍스트 인코더)로 표현하면 둘이 더 잘 보완되는가, 아니면 겹치는가 |
| 근거 | AlignRec(CIKM 2024): 콘텐츠 내부 정렬을 먼저 학습하면 특징이 좋아짐. 기존 4-5(텍스트가 강하면 이미지 몫이 준다) 통합 |
| 가설 | 방향을 정하기 어려움 → **탐색적 (양측)** 으로 사전 등록 |
| 조건 | 텍스트 SigLIP-text · MiniLM × 이미지 범용 SigLIP × (진짜 · 전체 섞기) × seed 3 |
| 코드 | `item_features`가 spec의 텍스트 임베딩 이름을 받도록 (현재 `text_minilm` 고정) |
| 비용 | 추출 몇 분 + 6~9회 |

### 4-8. [RQ3 · 재검증] 구매 기록이 적은 상품에서 이미지가 더 도움이 된다 — 우선순위 중간
| 항목 | 내용 |
|---|---|
| 근거 | 우리 사후: 희소 − 기존 +0.021 [+0.016, +0.027] (Marqo, 절대). 선행: VBPR 전체 +12% 대 콜드 +28%, PixelRec 콜드 상품 수 배 → **새 발견이 아니라 최신 인코더 · 섞은 이미지 대조군에서의 확인**으로 서술 |
| 가설 · 측정 | 절대 내용 기여도: 희소 > 기존, 신규 > 기존. 판매 횟수 연속 구간(0 · 1~2 · 3~9 · 10~49 · 50+) 추세 |
| 데이터 | 4-1과 같은 새 테스트 주 (실행 공유, 추가 학습 없음) |
| 해석 주의 | 판매 횟수는 인기도와 얽힘 → 인기도 입력 · logQ 모델(4-6)에서도 같은 방향인지 함께 보고 |

### 4-9. [RQ2 · 3 · 재검증 · 확장] ID 의존이 커질수록 기존 상품의 이미지 기여가 줄어든다 — 우선순위 중간
| 항목 | 내용 |
|---|---|
| 근거 | 우리 사후: 드롭아웃 0(i2)에서 기존 상품 기여 약 25% 감소. 선행: PixelRec — 기존 상품에서 Two-Tower(DSSM) 이미지 모델이 ID 모델보다 낮음, Frozen LVLM(Sun 외) — ID는 대체보다 **결합**이 낫다, AlignRec — 콘텐츠와 ID 정렬 |
| 가설 | ID 드롭아웃 {0, 0.1, 0.3, 0.5}에서 기존 상품 이미지 기여가 단조 증가. 추가: 최적 드롭아웃의 ID + 콘텐츠 모델이 ID 없는 모델보다 전체 R이 높다 |
| 선행 조건 | **강한 ID 모델**: ID 임베딩 가중치 감쇠 · 조기 종료로 ID 없는 모델 이상의 검증 성능을 먼저 확보 (현재 i4는 약 20% 낮음) |
| 데이터 | 새 테스트 주 |
| 비용 | 드롭아웃 4 × 조건 3 × seed 3 = 36회 |

- **10/16 실험 마감 기준 제안 배정** (팀 회의에서 확정)
  | 담당 | 가설 | 이유 |
  |---|---|---|
  | 김유환 (모델) | 4-3 텍스트 드롭아웃, 4-4 결합 구조 | `two_tower` 학습 · 모델 코드 수정 |

- **주 측정값에 전체 R을 넣는다** (4-0 원칙 1). "이미지를 이렇게 쓰면 텍스트 + 이미지 모델이 더 좋아진다"가 논문 메시지.
- **분량(3쪽):** RQ2에서 확증 1~2개(4-3 · 4-4 또는 4-6) + RQ1 기존 결과 + RQ3 사후 결과가 현실적. 패턴 가설은 한 줄로 줄인다.
